# 输入协议与 TL20 v1 快照

## UTF-8 日志

每个非空物理行含七列，以一个真实 Tab 字节分隔。接受 LF、CRLF、首行 UTF-8 BOM 和没有换行符的最后一行。空物理行跳过，仍计入来源行号。

| 字段 | 协议 |
|---|---|
| timestamp | 四位年和二位月日，T 后跟时分秒，可选 1～6 位小数秒，结尾必须有 Z 或 ±HH:MM。时分秒范围为 00～23、00～59、00～59 |
| level | 大写 TRACE、DEBUG、INFO、WARN、ERROR。命令行最低等级也接受小写 |
| component | 1～128 个 ASCII 字母、数字、点、下划线或连字符 |
| pid | 无符号 32 位十进制整数 |
| flags | 0～7 的十进制位掩码，三个位的业务含义由日志提供方约定 |
| duration_us | 无符号 64 位十进制微秒数，单个减号表示缺失 |
| message | 允许空字符串，须为合法 UTF-8。字段中禁止 Tab、CR、LF、NUL |

数值必须完整消费。行内容最多 65,536 字节，超长行按资源上限错误终止。示例文件可直接复制并在编辑器中打开。[demo.log](../data/demo.log)

## 二进制快照

所有多字节数均按小端存储。文本是 u32 字节长度加 UTF-8 内容。读入时验证载荷长度、实际剩余字节、字符串和分组数量上限。载荷上限为 2 MiB。

| 顺序 | 类型与内容 |
|---|---|
| 头 | 四个 ASCII 字节 TL20，u16 版本 1，u16 标志 0，u32 载荷字节数 |
| 查询 | 一个长度前缀文本，记录筛选条件与展示次序 |
| 计数 | 八个 u64，依次是 processed、invalid、matched、flag_bits、timed、total_us、min_us、max_us |
| 均值 | 一个 IEEE 754 binary64。timed 为零时计 0，展示为减号 |
| 等级 | 五个 u64，顺序同上面的等级列表 |
| 时间范围 | matched 大于零时写两个 i64，分别为首尾 UTC 时间距 Unix epoch 的微秒数 |
| 组件 | u32 行数。每行含组件文本和 u64 计数 |
| 分钟桶 | u32 行数。每行含 i64 UTC 分钟编号和 u64 计数，1970 年以前的编号为负 |

解码要求组键唯一、各组计数为正，各类分组的计数之和分别等于 matched。首尾时间和分钟桶需相符。耗时均值按原始计数和总量复算。文件须恰好在载荷末尾结束。格式保存聚合数据，时间线预览和详细诊断使用文本报告保存。[编解码实现](../src/snapshot.cpp)
