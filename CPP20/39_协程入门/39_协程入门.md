## 一、底层原理

### 1.1 协程是什么：能"暂停—续跑"的函数

普通函数一杆子到底；**协程**可以在中途**挂起**（保存全部局部状态），
把控制权交还调用者，之后再从断点**恢复**。关键字三个：

- `co_await expr`：按 awaiter 协议决定是否挂起；若 await_ready 为 true，
  或 await_suspend 返回 false，就不会保持挂起
- `co_yield expr`：把值交给 promise.yield_value，再按返回的 awaiter 决定
  是否挂起；本课生成器配置为存值并挂起
- `co_return`：结束协程（走 `return_void` / `return_value` 收尾）

函数体内出现这些协程关键字即成为协程，返回类型须能通过
`std::coroutine_traits` 找到对应 promise_type（常见方式是返回类型的嵌套类型）。

### 1.2 编译器替你做了什么

调用一个协程 ≠ 调用普通函数：

1. **分配协程帧**（通常动态分配，可优化掉）：保存 promise、参数副本、
   跨挂起点仍需存活的局部变量和状态；不必把所有局部变量都放入帧
2. 在帧里构造 **`promise_type`**：协程与调用方之间的"信箱"，
   编译器按固定契约调用它的成员
3. 执行体被改写成**状态机**：每个挂起点是一个"可跳回的标签"
4. 返回给调用者的是 `get_return_object()` 造的对象，内部握着
   **`coroutine_handle`**——恢复（`resume`）/销毁（`destroy`）的把手

**惰性生成器**的关键配置：`initial_suspend` 返回 `suspend_always`
——创建时函数体尚未执行（帧分配、参数复制和 promise 构造已发生），首次 `resume` 才进函数体（示例 ① 可视化验证）。

### 1.3 promise 六件套（最小生成器契约）

```cpp
struct promise_type {
    Gen get_return_object();                    // 造返回对象（握手）
    std::suspend_always initial_suspend();      // 创建时挂起？（惰性=挂）
    std::suspend_always final_suspend() noexcept;        // 收尾时挂起？（保帧可查 done）
    std::suspend_always yield_value(T v);       // co_yield 落点（存值+挂起）
    void return_void();                         // co_return 收尾
    void unhandled_exception();                 // 异常出口
};
```

`final_suspend` 返回 `suspend_always` 是**生成器的惯用配置**：
协程跑完后停在终态挂起点，帧还活着，`handle.done()` 才能为真——
若返回 `suspend_never`，帧立即销毁，之后再摸 handle 就是 UB。

### 1.4 两台发动机

协程的世界里有两方轮流开火：**调用者**（main）与**协程体**。
`resume()` 点火协程，协程跑到 `co_yield` 熄火交还——示例 ① 的打印顺序
（main 行与 coro 行交替出现）就是两台发动机轮换的直接证据。

## 二、具体语法

```cpp
Gen<int> trace(int n) {
    co_yield 1;                    // 挂起并留值
    co_return;                     // 结束（走 return_void）
}

auto g = trace(3);                 // 创建：body 未跑（initial 挂起）
auto value = g.next();             // 本课接口返回 optional<int>，无新值则 nullopt
g.done();                          // 是否停在 final_suspend

auto h = std::coroutine_handle<P>::from_promise(promise); // promise 是有效帧中的对象
h.promise();                       // 从有效句柄回到 promise，空句柄不能这样用
```

规则细则：

- 协程**不能**用：构造/析构函数、constexpr 函数、main、变长参数（`...`）
- `co_return expr` 需要 promise 提供 `return_value(expr)`；
  `co_return;`（或自然结束）配 `return_void()`——两者不可同时提供
- `co_yield e` 就是 `co_await promise.yield_value(e)` 的语法糖
- 帧的生命期由 handle 的 `destroy()` 终结；示例用 RAII 包装（析构时
  `if (h_) h_.destroy();`）
- 默认 `operator new` 分配帧；分配失败可走 `get_return_object_on_allocation_failure`
  在分配返回空指针时构造一个返回对象；否则分配失败通常抛 bad_alloc（进阶）
- 本机验证：g++ 15 + `-std=c++20` 直接编译，无需 `-fcoroutines`

## 三、实际应用与最佳实践

### 3.1 场景：惰性递推序列（示例 ③）

斐波那契生成器把 `a, b` 保存在帧里，按需递推。机器整数有界，示例在
下一项将溢出时结束，不能用有符号溢出来模拟数学上的无穷。协程适合表达
跨挂起点的复杂控制流（递推、解析器、状态机）；视图同样能保存状态、缓存
位置或生成值，并非只支持无状态逐元素变换。

### 3.2 场景：异步任务（本课只立框架）

把 `initial_suspend` 改成 `suspend_never`（急切启动）、把返回对象
改成"任务"，配合事件循环 `co_await` 网络事件——这就是 C++20 协程的
主战场（库：cppcoro、asio）。C++23 给出标准 `std::generator`（第 54 课）。

### 3.3 最佳实践清单

1. 先读懂数据流再动手：**拉（生成器）**还是**推（任务）**决定
   `initial_suspend` 与返回对象设计
2. 协程帧生命期用 RAII 对象托管；裸 handle 只出现在框架代码
3. **不跨 `co_yield` 持锁**：挂起点就是放弃执行权的地方，醒来时
   世界可能已变（对照第 38 课取消检查点）
4. `unhandled_exception` 用 `std::current_exception` 存入 promise，
   在生成器边界 rethrow；静默吞异常会把失败误报成正常结束
5. 手写 promise 是学习；工程里用现成库的 generator/task

## 常见陷阱

1. **忘了 final_suspend 挂起**：协程结束帧即销毁，之后任何
   `handle.done()/resume()` 都是 UB——生成器一律 `suspend_always`
2. 找不到 `std::coroutine_traits<返回类型, 参数类型...>::promise_type`
   就无法编译；返回类型的嵌套 promise_type 是默认 traits 的常用来源，
   也可按规则特化 coroutine_traits
3. 空句柄或已到 final_suspend 的句柄不能 resume；空句柄也不能 done。
   示例 `next()` 先检查句柄和终态，用 optional 区分产出值与正常结束，
   避免完成后返回上次 yield 的旧值
4. 协程参数按值传递会**搬进帧里**；引用参数悬垂的规则与 lambda 捕获
   同罪——挂起点放大了"谁还活着"的问题
5. 协程本身不创建线程或提供调度器；本例在同一线程交替执行。库也可把
   恢复工作安排到另一线程，此时仍需处理同步与生命周期
6. `return_void` 与 `return_value` 同时提供 → 编译错（契约二选一）

## 练习

1. 把 `initial_suspend` 换成 `suspend_never`，预测创建时的输出；同时
   修改 next() 的协议，使首次读取不跳过创建时已经 yield 的第一个值。
2. 给 `Gen<T>` 加 `begin()/end()`，让 range-for 直接消费生成器
   （提示：迭代器的 `operator++` 通过 next() 取得下一项，
   缓存 optional；`operator*` 返回其中的值，结束时与哨兵相等）。
3. 完成上题迭代器后，写 `range(a, b)` 生成器替代 `views::iota`，
   将生成器保存为左值再接 filter（或进一步实现可移动 view），
   体验"协程出数据 + 视图加工"的组合。
4. 阅读示例的异常转存与重抛路径，添加一个先 yield 再 throw 的协程，
   验证调用者能捕获异常，且帧仍由 RAII 正常销毁。
