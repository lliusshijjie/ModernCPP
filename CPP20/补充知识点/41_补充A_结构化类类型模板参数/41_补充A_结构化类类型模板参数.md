## 一、底层原理

### 1.1 模板可以接收一个类值

`Buffer<64>` 中的 64 是非类型模板实参。C++20 扩展了可用实参的类型，让满足结构化类型要求的类值也能参与模板实例化。文中用一个拥有字符数组的 `FixedString<N>` 保存名字，教学例子是 `Field<"level">`。

作这种用途的类必须是字面类，所有基类和非静态数据成员均为公开、非 `mutable`，并且类型本身是结构化类型或其数组。固定大小的字符数组满足要求。

### 1.2 内容和地址有不同语义

`Field<"level">` 的字面量先用来构造一个 `FixedString`，字符复制进它自己的数组。模板身份因此依赖实参类型和值，同样的内容得到相同的特化。直接使用字符串字面量作为指针类型的模板实参，则受非类型模板实参的地址规则限制。

当使用类类型模板参数时，`Name` 指代具有静态存储期的 const 模板参数对象。所以例子中 `Name.view()` 可以给静态成员使用。普通局部 `FixedString` 上取得的视图仍然受该局部对象的生命周期约束。

## 二、具体语法

```cpp
template<std::size_t N>
struct FixedString {
    char value[N]{};

    constexpr FixedString(const char (&text)[N]) {
        for (std::size_t i = 0; i < N; ++i) {
            value[i] = text[i];
        }
    }
};

template<FixedString Name>
struct Field {};

using Severity = Field<"level">;
```

构造函数接收字符数组引用，`N` 包括末尾的零字节。类模板实参推导从字面量确定 `N`。配套示例中的 `view()` 用 `N - 1` 保留字符串内容长度。

## 三、实际应用与最佳实践

`read_field<"level">(event)` 和 `read_field<"pid">(event)` 使用同一个入口。Concepts 检查名字，`if constexpr` 在不同实例中选择对应成员。

- 字段集合固定，写错名字会在编译时违反约束。
- `event` 的值可以来自运行时。模板固定的是选择哪个字段。
- 来自文件或 CLI 的字段名在运行时才知道，适合使用查找表等运行时分发方式。两种接口可以服务同一份数据模型。

阅读示例时先画出 `"level" → FixedString<6> → Field 的模板实参`，再看名字如何约束字段访问。

## 常见陷阱

1. 将数组改成私有成员或 `mutable` 成员，会破坏该类作为结构化类型的条件。
2. 把任意运行时字符串放到尖括号里，会缺少满足模板实参要求的常量值。
3. 把 `FixedString::view()` 当成拥有字符串，普通临时对象消失后视图可能悬垂。
