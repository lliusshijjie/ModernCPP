## 一、底层原理

### 1.1 能在编译期求值，不等于每次都需要

`constexpr` 函数可以在符合规则时参与常量求值，也可以在运行时执行。用它初始化一个 `constexpr` 变量时，初始化表达式必须满足常量求值要求。用它初始化示例里的普通局部 `bool` 时，不同的求值上下文会得到不同的结果。

`std::is_constant_evaluated()` 查询的是当前调用是否正在标准规定的常量求值上下文中。它不报告优化器是否把某个普通调用提前算完。编译器可以优化运行时分支，仍须保持该分支的可观察语义。

### 1.2 两条路径可以共用一份承诺

在 C++20 中，`std::memset` 不能用于常量求值。可以让编译期路径逐个字节写零，运行时路径调用 `memset`。两条路径都接受同一段连续字节并清零，调用方得到一致结果。选择它们的目的是适配不同求值上下文，性能需要另行测量。

## 二、具体语法

```cpp
#include <type_traits>

constexpr bool in_constant_context() {
    return std::is_constant_evaluated();
}

constexpr bool compile_time = in_constant_context();  // true

void example() {
    bool runtime = in_constant_context();             // false
    (void)runtime;
}
```

在 `constexpr` 函数里用**普通 `if`** 选择两条路径。`if constexpr` 的条件本身需要在常量上下文中求值，所以直接写 `if constexpr (std::is_constant_evaluated())` 时条件始终为真，失去了识别调用场景的作用。

有些静态初始化或引用初始化等场景允许编译器先尝试常量求值。不要把试算中观察到的分支当作程序的可移植行为。本课用 `constexpr` 变量和普通局部 `bool` 清楚地固定演示上下文。

## 三、实际应用与最佳实践

`clear_bytes` 接受 `span<unsigned char>`。空视图直接返回，以免将空指针交给底层字节操作。固定数组和运行时缓冲区使用同一个入口。

- 编译期构造四字节数组，只清空中间两个元素，用 `static_assert` 验证结果。
- 运行时对不同的初始数据清理相同子区间，比较两条路径的结果并检查两侧哨兵字节。
- 如果一个已支持常量求值的标准算法足以表达操作，可以直接使用它。双路径适合确有两种实现需求的场合。

接到第 40 课时，`consteval` 适合只允许立即调用的接口，`constexpr` 适合两边都能使用的接口。CPP23 第 58 课的 `if consteval` 还涉及立即函数上下文，适合在本课之后对照阅读。

## 常见陷阱

1. 直接用 `if constexpr` 包住 `std::is_constant_evaluated()`，导致运行时也进入常量分支。
2. 用 `constexpr bool flag = std::is_constant_evaluated()` 保存标志，再用它区分调用场景。该初始化本身就是常量求值。
3. 只测编译期路径。运行时路径还要覆盖空区间、子区间和边界数据。
