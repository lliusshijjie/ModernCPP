# 第 35 课 · 三路比较 <=> 与统一比较（C++20）

> 所需标准：**C++20**（`-std=c++20`）｜ 讲解：本文件 ｜ 独立代码：`35_spaceship.cpp`
> 前置：第 31 课（concepts——`std::three_way_comparable` 用到它）

## 一、底层原理

### 1.1 旧世界：六个运算符的排列组合地狱

想让自定义类型支持全套比较？C++17 要手写 6 个运算符（`== != < <= > >=`），
写错一个（比如 `<` 里把 `<=` 打进去）就埋雷。`std::tie` 能救一时，
但成员一多照样啰嗦——而且"相等"与"有序"两套语义没有类型层面的区分。

### 1.2 `<=>`（宇宙飞船）：一次表达"谁大谁小还是相等"

```cpp
struct Ver {
    int major, minor, patch;
    auto operator<=>(const Ver&) const = default;   // 一行顶六个
    bool operator==(const Ver&) const = default;
};
```

内建 `<=>` 和典型的自定义比较返回以下比较类别，而不是 -1/0/1 整数。
手写的 `operator<=>` 在语言层面也允许返回其他类型：

| 类别 | 语义 | 典型来源 | 特性 |
|---|---|---|---|
| `strong_ordering` | 全序且**可替换**（比较相关的公开状态无可观察差异，并非逐位相同） | int | `less/equal/greater` |
| `weak_ordering` | 全序但只有**等价**（大小写不同的名字） | 自定义排序 | `less/equivalent/greater` |
| `partial_ordering` | 存在**不可比**对 | 浮点 NaN | 多一个 `unordered` |

类别只能**由强放宽**：strong → weak → partial 合法，反向不行。

### 1.3 编译器替你写：defaulted 的规则

- `auto operator<=>(...) = default`：逐成员按**声明序**比较（基类先比），
  返回类型 auto 推导为**成员类别中最宽的**——有一个 double 成员，整型成员
  陪着降级成 `partial_ordering`
- **显式声明更严的返回类别**不会自动"压平"成员：比如成员含 double、
  返回类型写 `strong_ordering`——该函数被**隐式删除**（调用即编译错）。
  想要"double 也强序"必须手写函数体，用 `std::strong_order(v, o.v)` 逐个压平
- **static 成员不参与比较**；数组成员按元素序比较
- `==` 独立于 `<=>`：defaulted `==` 逐成员用 `==` 比较（可短路）。
  类内 default 的 `<=>` 在没有显式声明 `==` 时，会隐式声明一个 default 的
  `==`，它不是通过 `(a <=> b) == 0` 实现。**手写函数体的 `<=>` 不会自动
  生成 `==`**，需另行定义；显式写出两个 default 也合法

### 1.4 重写规则：六个旧运算符全部"借道"

没有手写 `<` 时，`a < b` 由编译器重写为 `(a <=> b) < 0`；同理
`a >= b` → `(a <=> b) >= 0`。`!=` 由 `==` 取反，`==` 还可反向重写
（`b == a`）。因此只声明了 default 的 `<=>`、并成功获得隐式 `==` 的
值类型，也能用于 map、排序和去重；手写 `<=>` 时需自行补齐所需的相等比较。

## 二、具体语法

```cpp
auto c1 = 1 <=> 2;                    // strong_ordering::less
auto c2 = 1.0 <=> 2.0;                // partial_ordering::less
auto c3 = 0.0 <=> -0.0;               // partial_ordering::equivalent

double nan = ...;
(nan <=> 1.0) == std::partial_ordering::unordered;   // NaN 不可比（判定法）
std::is_lt(x <=> y);                  // is_lt/is_gt/is_eq/is_neq/is_lteq/is_gteq

std::strong_order(2.0, 2.0);          // 定制点：同类型强制强序
std::strong_order(nan, 1.0);          // IEC 60559 实现上，正 NaN 大于所有数值；负 NaN 小于所有数值

std::weak_ordering w = Ver{} <=> Ver{};            // strong 放宽为 weak，OK
// std::strong_ordering s = Score{} <=> Score{};   // partial 收紧为 strong，编译错
```

规则细则：

- 比较类别三值皆可 `==` 比较：`c == std::strong_ordering::equal`
- **没有 `std::is_unordered`**——判定不可比直接与
  `std::partial_ordering::unordered` 比较
- `std::strong_order / weak_order / partial_order` 是定制点：
  形参须**同类型**（`double` 和 `float` 混用直接编译错）
- defaulted `<=>` 返回 `auto` 时由子对象的比较类别推导结果；显式写类别
  时也可按规则从子对象的 `==` 与 `<` 合成比较，不能一概等同于强制转换
- 成员序 = 声明序：想"先比 minor 再比 major"只能调整声明顺序，default 不认其他序

## 三、实际应用与最佳实践

### 3.1 场景：版本号/坐标类一步到位（示例 ①/③）

`Ver` 两个 default 一写，`sort` / `map` 键 / `unique` / `==` 全部可用——
旧世界六运算符 + `std::tie` 的样板全部消失（示例 ③ 的 map 用法）。

### 3.2 场景：浮点成员的类别决策（示例 ②）

若需要包含 NaN 的全序，可用 `std::strong_order` 并让 `==` 使用一致语义。
在 IEC 60559 实现上，它还区分 `+0.0` 与 `-0.0`；直接 default 的浮点 `==`
却把二者视为相等，并把 NaN 视为不等，因而不能随意混搭。若保留
`partial_ordering`，下游需处理 unordered；排序和 map 的比较器必须满足
严格弱序，不能直接把含 NaN 的普通浮点 `<` 当作合格比较器。

### 3.3 最佳实践清单

1. 值语义的数据类：`<=>` 与 `==` 成对 default，两行结束
2. 返回类型用 `auto`；确有类别需求（如禁止 unordered 进 map）再显式声明
3. 浮点参与比较时**想清楚类别**：强序要手写压平，别指望 default
4. 等价与相等语义不同时（大小写不敏感排序）选 `weak_ordering` 手写
5. 需要一致的三路比较接口时用 `std::three_way_comparable<T>` 约束；
   默认比较类别要求为 partial_ordering。要求 strong_ordering 时可写
   `std::three_way_comparable<T, std::strong_ordering>`，语义契约仍须由实现者保证

## 常见陷阱

1. **声明 `strong_ordering` 却有 double 成员**：defaulted 函数被隐式删除，
   调用处报"use of deleted function"——病根在类别不匹配，不在调用处
2. 找 `std::is_unordered` 找不到不是你眼花：标准只提供 is_lt/is_gt 等
   六个谓词，unordered 判定要与 `partial_ordering::unordered` 相比较
3. `std::strong_order(double_val, float_val)` 编译错：定制点要求同类型，
   先自己统一再调用
4. NaN 参与普通比较时，`== < <= > >=` 均为 false，`!=` 为 true；
   在 `<=>` 世界显式化为 `unordered`——把 `false` 翻译成"不可比"再推理
5. default 的 `<=>` 可隐式声明 default 的 `==`；手写 `<=>` 不会。
   自定义比较时要确保相等与排序等价语义一致
6. static 成员被静默跳过——把"参与排序的字段"全写成非 static 数据成员

## 练习

1. 给 `Point2D{int x, y; ...}` 全套 default 比较；把 y 声明在 x 前面，
   解释 `(0,1)` 与 `(1,0)` 谁小，再用 static_assert 固定结论。
2. 手写大小写不敏感的 `Name`：`weak_ordering` 的 `<=>` + 相应 `==`，

3. 在 `numeric_limits<double>::is_iec559` 为 true 的实现上，使用
   `std::copysign(quiet_NaN(), 1.0)` 与 `std::copysign(..., -1.0)` 明确 NaN 符号，
   验证普通 `<=>` 返回 unordered，而 `strong_order` 把正/负 NaN 排在数值两端。
4. 把你现有代码里手写 `operator<` 的类换成 defaulted `<=>`，
   统计删掉的行数与新增行数。
