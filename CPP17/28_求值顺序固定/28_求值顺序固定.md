# 第 28 课 · 求值顺序固定（P0145）（C++17）

> 所需标准：**C++17** ｜ 讲解：本文件 ｜ 独立代码：`28_evaluation_order.cpp`
> 前置：第 04 课（make_unique 与异常安全缺口——本课兑现"已堵上"的承诺）

## 一、底层原理

### 1.1 旧世界：求值顺序大多"未指定"，交错直接 UB

C++14 里，`f(a(), b())` 两个实参**谁先谁后未指定**，更糟的是允许**交错**
（一个实参求到一半去求另一个）。于是这些写法全是雷：

| 表达式 | C++14 的命运 |
|---|---|
| `f(i++, i++)` | 两次修改无排序 → **未定义行为** |
| `std::cout << i << i++` | UB（各编译器输出不同） |
| `f(unique_ptr<T>(new T), may_throw())` | `new` 完成后、构造前 `may_throw` 抛 → **泄漏**（第 04 课的缺口） |

### 1.2 P0145 的核心：把"未排序"收紧为"不确定顺序"

C++17 不是规定"从左到右"，而是把关键关系从 **unsequenced（可交错）**
收紧为 **indeterminately sequenced（二选一，但不交错）**：

| 场景 | C++17 规则 |
|---|---|
| 函数调用 | 后缀表达式（函数对象）先于每个实参 |
| 实参之间 | **每个实参的求值+副作用完整完成后**，下一个才开始 |
| 赋值 `E1 = E2` | **右操作数先于左操作数**（新规则） |
| `E1[E2]`、`E1.E2`、`E1->E2`、`E1<<E2` | E1 先于 E2 |
| `&&`、`\|\|`、`,` | 本来就短路/顺序（不变） |

三档区别记牢：

- **sequenced**：顺序确定（如 `&&` 左先右后）
- **indeterminately sequenced**（C++17 实参）：谁先不定，但**互不交错**
- **unsequenced**（C++17 仍在，如 `+` 的两操作数）：无排序，双双修改同一变量 = UB

### 1.3 这如何关闭第 04 课的泄漏缺口

`f(unique_ptr<T>(new T), g())`：两个实参不交错——若 uptr 实参先求值，
则 `new + 构造 + 接管` **全部完成**后才轮到 `g()`；`g()` 抛异常时 uptr
早已是完整对象，栈展开时正常析构。反过来 `g()` 先求值则对象根本没创建。
**无论编译器选哪种顺序都不可能泄漏**——交错这个"第三态"被消灭了。

## 二、具体语法（行为对照速查）

```cpp
int i = 0;
std::cout << i << i++;   // C++17："00"（左 << 先于右）；C++14：UB
std::cout << i++ << i;   // C++17："01"；C++14：UB
i = i++;                 // C++17：良定义，i 回到 0（RHS 先完成）；C++14：UB
f(i++, i++);             // C++17：无 UB，但 (0,1)/(1,0) 未指定 —— 别写！
i++ + i++;               // 仍是 UB！二元 + 不排序
```

规则细则：

- **优先级/结合律 ≠ 求值顺序**：三码事。`a + b * c` 结合律定了"怎么组合"，
  各部分"谁先算"是求值顺序的事
- 实参顺序仍未指定——**可移植代码永远别依赖实参顺序**，拆成多行
- 成员调用 `obj.fn(args)`：obj 的求值先于 args

## 三、实际应用与最佳实践

### 3.1 场景：智能指针实参的异常安全（示例 ③-1）

裸 `unique_ptr<T>(new T)` 与可能抛异常的表达式同框——C++17 起语言保证
无泄漏窗口。当然，工程上仍优先 `make_unique`（第 04 课清单不变）。

### 3.2 场景：输出流的链式调用终于可预测（示例 ①）

`cout << i << i++` 在 C++14 是面试名题（各编译器输出不同），C++17 有
唯一答案——但答案依赖微妙规则，**别写出这种代码**，理解它是为了读旧代码。

### 3.3 最佳实践清单

1. 依赖实参顺序的逻辑一律拆成多条语句——C++17 只是"无害化"，不是"定序"
2. `i = i++` 虽已良定义，可读性仍为零——review 直接打回
3. 二元运算符两侧别放修改同一变量的表达式（`+` 们仍是 unsequenced）
4. 升级 C++17 时，把过去为规避 UB 加的临时变量清理掉（行为已有保证）
5. 面试/教学语境：能用 P0145 三档术语讲清 "为什么以前是 UB"

## 常见陷阱

1. **以为 C++17 规定了实参从左到右**——没有！只是不交错、无 UB
2. `f(i++, i++)` 不再 UB ≠ 结果确定——两种顺序仍任选
3. `i++ + i++` 在 C++17 仍是 UB——只有列表里的那些运算符被定序
4. 把优先级当求值顺序讲——`f(g(), h())` 与优先级毫无关系
5. 依赖"我的编译器恰好从左到右"——换编译器/优化等级就翻脸
