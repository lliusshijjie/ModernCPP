# 第 27 课 · 强制拷贝消除与值类别（C++17）

> 所需标准：**C++17** ｜ 讲解：本文件 ｜ 独立代码：`27_copy_elision.cpp`

## 一、底层原理

### 1.1 C++17 之前：拷贝消除是"恩赐"不是"权利"

`T x = T{7};`、`return T(args);` 这类**纯右值（prvalue）**场景，C++14 允许
编译器优化掉拷贝/移动（RVO），但**标准不保证**——而且即使优化器确实消除了，
**拷贝/移动构造函数也必须存在且可访问**（重载决议要先能选中它）。
两个恶果：

- 不可拷贝不可移动的类型无法按值返回（编译错误）
- 代码的行为"取决于编译器心情"，计数、副作用不可移植

### 1.2 C++17 的语义手术：prvalue 不再是"对象"，是"配方"

P0135 重定义 prvalue 为**未物化的值**——它不再是"一个已构造好的临时对象"，
而是"如何构造一个对象的**配方**"。用同类型 prvalue 初始化目标对象时，
可以在目标位置直接构造，不需要中间对象的拷贝/移动。
绑定引用、访问临时对象成员等场景仍可能触发**临时对象物化**，不能理解为临时对象消失。

### 1.3 消除的三档待遇（本课示例逐行实证）

| 场景 | C++17 待遇 | 额外拷贝/移动要求 |
|---|---|---|
| `T x = T{...}` / prvalue 传参 / `return T(...)` | **强制消除**（直达构造） | **不要求** |
| NRVO：`T local; return local;`（具名局部） | 可选优化 | 未消除时需有可用的拷贝/移动路径 |
| 参数返回 `return in;` | 参数不参与 NRVO，按规则尝试隐式移动 | 由重载决议选定拷贝或移动 |

### 1.4 值类别三分法（C++11 提出，C++17 后才真正自洽）

| 类别 | 直觉 | 例子 |
|---|---|---|
| lvalue | 有名字、可取地址 | `x`、`*p`、字符串字面量 |
| **prvalue** | **构造配方**（未物化） | `42`、`T{}`、按值返回 `make()` 的调用式 |
| xvalue | "将亡"——可被移动的源头 | `std::move(x)`、`static_cast<T&&>(x)` |

C++17 的一句话版本：**lvalue/xvalue 是真对象，prvalue 只是图纸**；
`std::move` 不移动任何东西，只是把 lvalue 变成 xvalue（授权移动）。

## 二、具体语法

```cpp
Traced a = Traced(7);            // ① 强制消除：一次直达构造
Traced t = make_prvalue(5);      // ② prvalue 返回：强制消除
sink(Traced(3));                 // ③ prvalue 实参 → 参数位置直达构造
Traced u = std::move(t);         // ④ xvalue：移动构造（真的发生移动）
struct Sealed {
    explicit Sealed(int) {}
    Sealed(const Sealed&) = delete;
    Sealed(Sealed&&) = delete;
};
Sealed make_sealed() { return Sealed{42}; } // ⑤ C++17 合法！（C++14 编译错）
```

规则细则：

- `-fno-elide-constructors` 只能关掉**可选**消除（NRVO），
  关不掉强制部分——prvalue 该直达还是直达
- 函数参数与异常处理器参数不参与 NRVO；try 块中的普通局部对象不因位于 try 内就被排除
- 强制消除不要求拷贝/移动构造可用，但仍须满足析构函数可访问、未删除等要求
- 返回局部变量**不要写 `std::move(local)`**——把 NRVO 机会直接掐死
  （还禁用了直达优化），纯负优化

## 三、实际应用与最佳实践

### 3.1 场景：工厂与管道零拷贝（示例 ③-1）

`auto cfg = parse(load(read(file)));` 中，同类型 prvalue 初始化相应目标时可以
直接构造；但每个阶段仍可能创建自己的结果对象，不能统一算成一次构造。
如果某个阶段返回具名参数，该返回也不参与 NRVO，需要另行分析拷贝/移动。

### 3.2 场景：不可移动类型的按值接口（示例 ③-2）

锁守卫、RAII 哨兵等"禁止复制也懒得写移动"的类型，C++17 起可以拥有
按值返回的工厂——语言保证不产生副本。

### 3.3 最佳实践清单

1. 工厂可以优先考虑按值返回；具体成本要区分 prvalue 直达构造、NRVO 与参数返回
2. 返回具名局部**不加** `std::move`（保住 NRVO）；返回参数也不加
   （语言已隐式移动）
3. 调试拷贝/移动次数：抄本课的 `Traced` 计数器——数字不说谎
4. movable-only 依赖消除的代码升级 C++17 后可顺手简化
5. 需要确认消除是否发生：看 Traced 计数，别看汇编猜

## 常见陷阱

1. **以为 NRVO 也被保证了**——没有；跨编译器/加 -fno-elide 会看到移动
2. `return std::move(local);` 反模式：禁用 NRVO，白付一次移动
3. 以为 `std::move(t)` 会"移动"——它只是造 xvalue；真正移动发生在
   重载决议选中移动构造/赋值时
4. 函数形参按值接 prvalue 是直达构造；但接 **lvalue 实参是拷贝**——
   混用场景下计数会超出直觉（示例 ②-3 的 relay 演示）
5. C++14 时代为"万一没消除"保留的拷贝构造——升级后别急着删，
   先用 Traced/静态断言确认无其他使用点

## 练习

1. 用 `-fno-elide-constructors` 重跑示例，逐行对比计数差异，
   圈出哪些行**不变**（强制消除）、哪些行**+1 移动**（NRVO 被关）。
2. 把 `make_named` 改成 `return std::move(local);`，观察 NRVO 消失
   （move +1），体会反模式的代价。
3. 给 `Sealed` 加 `operator<<` 打印成员，验证它整个生命周期只有一次构造。
4. 写三层管道 `parse(load(read()))`（全按值返回 Traced），验证计数：
   总构造次数 = 3、拷贝 = 移动 = 0。
