# AssetForge17 · 可复现的本地资源包构建器

本文记录工程设计和验收规格。构建、运行与代码入口见 [README](README.md)，练习顺序见 [学习指南](STUDY_GUIDE.md)。

AssetForge17 读取资源清单，选出某个构建配置需要的资源及其传递依赖，将它们按固定顺序写进一个二进制资源包。消费方可以列出包中的资源，按 ID 或别名查找条目，并校验内容。

MiniKV17 的核心是可变数据的写入与恢复。AssetForge17 的核心是**依赖闭包、拓扑排序和确定性文件布局**。一次构建的产物可以直接交给另一个程序读取，也能用逐字节比较验证构建是否可复现。

## 1. 完成后的使用方式

| 场景 | 命令 | 行为 |
|---|---|---|
| 查看构建计划 | `assetforge plan demo.assets --profile demo` | 输出选中的资源、依赖顺序和可用别名 |
| 从单个资源开始规划 | `assetforge plan demo.assets --root startup` | 将别名解析为稳定 ID，再计算传递依赖 |
| 构建资源包 | `assetforge build demo.assets --profile demo --out out/demo.afp` | 准备数据、检查上限、写入并验证新文件，可用 `--report normalization` 显示行尾处理统计 |
| 查找包中资源 | `assetforge inspect out/demo.afp --id startup --detail` | 输出条目大小、依赖、校验值和别名 |
| 验证包 | `assetforge verify out/demo.afp --policy seq` | 检查索引布局并逐条校验资源内容 |
| 调整当前工作区 | `assetforge shell demo.assets --profile demo` | 在同一会话内切换配置、重载清单、改别名和重新规划 |

一次性命令要求明确指定 `--profile` 或 `--root` 其中之一。会话中的别名修改只写入内存，随后构建的包使用修改后的别名。构建和校验也可由其他 C++ 程序通过库接口调用。

V1 使用 C++17、CMake 和 CTest，核心依赖标准库。主题集中在小型离线资源包，采用原样字节与行尾规范化两种资源处理模式。CLI 以 0 表示成功，1 表示校验、查找或构建失败，2 表示命令行用法错误。工作区内一次指令失败后仍可继续查询或构建。

## 2. 从三条资源算出一个包

清单使用 UTF-8 文本。下面的列之间是 Tab，资源路径以清单所在目录为基准。

~~~text
asset	ui.start	text-lf	scene/start.txt	128
asset	ui.logo	raw	art/logo.bin	-
asset	ui.theme	text-lf	config/theme.txt	-
asset	ui.extra	raw	art/extra.txt	-
requires	ui.start	ui.theme
requires	ui.start	ui.logo
alias	startup	ui.start
profile	demo	ui.start
~~~

| 指令 | 含义 |
|---|---|
| `asset ID MODE PATH LIMIT` | 定义稳定 ID、处理模式、相对路径和处理后字节数上限。单个减号表示采用默认上限，数字 0 表示只接受空结果 |
| `requires ID DEP` | 第一个资源依赖第二个资源。两个操作数均使用稳定 ID |
| `alias NAME ID` | 定义可供查询的公开名称。别名指向稳定 ID，和稳定 ID 共用名字空间 |
| `profile NAME ROOTS` | 定义一组根资源。多个稳定 ID 用逗号分隔 |

ID、别名和配置名为小写 ASCII，允许数字、点、下划线和连字符，最多 64 字节。路径字段允许空格。支持空行和以 `#` 开头的整行注释。先读完清单再解析名称，所以前向引用有效。重复 ID、重复别名、重名冲突、未知端点和重复依赖边都会给出带物理行号的诊断。清单加载时检查整个依赖图。

假设 `logo.bin` 是十六进制字节 `00 7f ff`，另外两个文件分别是 ASCII 文本 `accent=blue\r\n` 和 `title=Demo\r\n`。`raw` 原样保留所有字节。`text-lf` 将每对 CRLF 变为 LF，遇到单独的 CR 或 NUL 时报告错误，其余字节照录。

| 包内序号 | ID | 依赖序号 | 内容区相对偏移 | 大小 |
|---:|---|---|---:|---:|
| 0 | ui.logo | 空 | 0 | 3 |
| 1 | ui.theme | 空 | 3 | 12 |
| 2 | ui.start | 0、1 | 15 | 11 |

从 `demo` 构建得到 **3 条资源、2 条依赖、1 个别名、26 字节内容**。`ui.extra` 不在依赖闭包中，构建过程不打开它的文件。包内查询 `startup` 命中第 2 条资源。若在会话中把 `startup` 改成 `launch`，下一次构建的别名表会变化，三条资源的内容和依赖顺序保持一致。

## 3. 数据流和模块

~~~mermaid
flowchart LR
    A[资源清单] --> B[Catalog 解析与引用校验]
    B --> C[Workspace 取得配置和目录快照]
    C --> D[Planner 计算闭包与拓扑顺序]
    D --> E[Builder 读取并准备资源]
    E --> F[并行测算独立资源的校验值]
    F --> G[BundleWriter 写入索引与数据]
    G --> H[BundleReader 核验并发布]
    D --> I[计划预览]
    H --> J[索引查找和校验报告]
~~~

| 模块 | 主要类型 | 职责 |
|---|---|---|
| `manifest` | `ManifestRecord`、`AssetSpec`、`Diagnostic` | 解析单行指令，保留声明位置，校验名称和字段 |
| `catalog` | `Catalog`、`Workspace`、`WorkspaceSnapshot` | 维护资源、依赖、别名和当前配置，提供拥有型快照 |
| `planner` | `BuildPlan`、`PlannedAsset` | 从根资源求闭包，确定构建顺序和包内序号 |
| `builder` | `PrepareJob`、`PreparedAsset`、`BuildSummary` | 读取源文件、规范化内容、检查容量、计算 CRC |
| `bundle` | `BundleHeader`、`BundleWriter`、`BundleReader` | 定义线格式，编解码，按名称定位条目，验证包 |
| `report` | `ReportRegistry`、`ExtraReport` | 输出基础统计和注册的扩展报告 |
| `cli` | `Command`、`CommandResult` | 解析参数、分发操作、输出诊断 |

**拥有关系。** 解析器用 `string_view` 切分当前行，Catalog 复制并拥有路径、ID 和引用。BuildPlan 按值拥有闭包内的资源描述和匹配的别名，可以在重载之后继续使用。PreparedAsset 拥有处理后的原始字节。校验阶段只借用稳定缓冲区，阶段结束后读者与缓冲区一起释放。

**错误表示。** 查询无此 ID 和没有显式资源上限用 `optional`。已知指令集合与可预期结果用 `variant`，例如 `BuildSummary | BuildError`。一个清单语法错误应保留行号，构建 I/O 错误应保留资源 ID 和路径。扩展报告的开放类型值用 `any`，转交给登记时配对的格式化器。

## 4. 依赖图与确定性

1. 建目录后校验每条边的两个端点。约定 `requires parent child` 在业务上是 parent 依赖 child，调度邻接表从 child 指向等待它的 parent。
2. 从所选根资源迭代遍历依赖，给每个稳定 ID 去重。一个共享依赖只准备和写入一次。
3. 对闭包运行 Kahn 拓扑排序。每一步从就绪集合取字典序最小的稳定 ID。若处理数不足，用迭代 DFS 在剩余子图中找出一条实际环路，诊断形如 `ui.start -> ui.theme -> ui.start`。载入完整清单时也用同一排序逻辑检查环路。
4. 按拓扑结果为资源编号。每条依赖转换成比当前条目更小的序号，升序写入。同一包里的别名表按名称排序，仅包含指向已选资源的别名。

拓扑排序使用最小堆，闭包求解和判环本身按节点与边线性遍历。若已将名称索引化，整个规划的主要开销为 `O(V + E + V log V)`，其中 V、E 为参与排序的图规模。名称解析和依赖序号排序另计。

给定相同的资源 ID、依赖、别名、根集合以及处理后的内容，包的字节应相同。声明顺序、输入文件的绝对路径、构建时刻和执行策略均不进入包。主索引和内容区同用拓扑顺序，报告可另按 ID 展示。

## 5. 构建阶段与工作区

**准备。** 每个 PrepareJob 持有源路径、处理策略和上限。策略是 `RawSource | TextLfSource`，由 `visit` 进入统一准备函数，在其中用 `if constexpr` 区分原样移交缓冲区和规范化行尾。检查选中资源的相对路径，解析后按路径组件确认普通文件位于清单根目录内，再以二进制模式读取。构建期间由调用方保持清单和源文件稳定。工作区快照固定的是清单与选择信息，文件内容在 Builder 读取时取得。

**校验。** 先完成 I/O、分配和范围检查，再在 `seq` 或 `par` 下用 `std::transform` 为每块独立数据计算 CRC32。每个调用只读一块、返回一个定长结果，回调内不分配、不记录日志、不持锁，策略算法之外比较校验值和生成诊断。算法允许并行，实际是否并行由工具链决定。标准 `par` 下，元素回调的未捕获异常会触发终止。[C++17 草案 · parallel_policy](https://timsong-cpp.github.io/cppwp/n4659/execpol.par)

**发布。** 调用方在构建期间独占输出路径。目标文件必须尚不存在。创建缺失的父目录，在同一父目录下建立临时工作目录，写入完整包并关闭流。用同一个 BundleReader 重新读入并验证，关闭 Reader 后将文件改名发布。失败时清理临时文件，报告具体失败阶段。成功时成品可打开、可校验。

**并发 API。** Workspace 分别持有目录（资源、别名和配置定义）与当前选中的配置。目录查询与查询配置名可各自持共享锁。生成 BuildPlan 时通过两个延迟加锁的 `shared_lock` 和 `std::lock` 同时取得两侧读权限，取完拥有型快照即释放。重载和切换配置需要在同一临界区确认配置与目录相容，用 `scoped_lock` 获取两个互斥量的独占权限。重载在锁外解析、验证候选目录，若新目录没有当前配置则返回错误。别名更改只写目录。磁盘 I/O、拓扑排序、扩展报告和打包在锁外执行。

**别名改名。** 在独占锁下用 `map::extract` 取出旧别名，再替换节点键并插回同一张表。改名参数的字符串在提取前准备好，换键用交换。新名撞到稳定 ID 时直接拒绝，撞到已有别名时从失败插入的返回值取回节点，换回原键并恢复。旧名等于新名且存在时成功。依赖图和配置根始终引用稳定 ID。

## 6. AFP v1 线格式

固定小端。字段逐个编码，字节序列用 `vector<byte>` 表示。读者先验证头和长度，再读取索引并生成内容区块描述。

| 区块 | 内容 |
|---|---|
| 固定包头 | 4 字节魔数 `AFP1`，u16 版本，u16 保留位，u32 资源数，u32 别名数，u32 索引字节数，u32 索引 CRC32，u64 内容区字节数 |
| 资源索引 | 每条依次是 ID、u64 内容区相对偏移、u64 长度、u32 内容 CRC32、u32 依赖数、依赖序号数组 |
| 别名索引 | 每条是别名与 u32 目标资源序号，位于同一索引区 |
| 内容区 | 按资源索引顺序紧密拼接，无对齐填充 |

名称采用 u16 长度前缀加对应 ASCII 字节，依赖序号使用 u32。保留位为零。CRC 采用 CRC-32/ISO-HDLC，以 `123456789 → 0xcbf43926` 作为固定验证向量。索引 CRC 覆盖整个索引区，每条资源 CRC 覆盖处理后的内容。该校验针对意外损坏。

验证器检查 magic、版本、实际文件大小、索引 CRC、所有名称、依赖序号、别名目标和区块边界。每条资源偏移必须等于上条资源结束处，校验 `length <= remaining` 后才推进游标，允许相邻零长度记录共享边界。索引和内容必须恰好消费完。比较版本后才按对应布局解析。文件头和索引中的计数都要先过上限再分配内存。

初始上限定为 4,096 条资源、16,384 条依赖、4,096 个别名，单文件 8 MiB、聚合源数据和最终内容分别最多 64 MiB，索引最多 2 MiB。每个文件按实际读取量检查大小。包格式保存资源 ID 而非源路径，读取器按 ID 提供预览和字节读取接口。

| 19 三种类型的取舍 | 缺失字段、封闭的输入与错误集合、开放的报告扩展 | 核心计划与包格式使用显式类型，扩展报告只影响展示 |

| 21 `filesystem` | 求根路径、解析相对资源路径、创建输出目录、阶段文件发布 | 路径错误和 I/O 错误可定位到对应资源 |
| 22 属性 | `nodiscard` 标注计划与验证结果，`maybe_unused` 标注仅断言使用的局部量，`fallthrough` 用于详细预览追加通用摘要 | Release 构建干净，详细输出的两段各出现一次 |
| 23 `scoped_lock` / `shared_mutex` | 目录允许多个读者，重载时检查当前配置，规划时获取一致快照 | 并发读者只能看到完整的旧版本或新版本 |
| 24 `charconv` | `from_chars` 解析字节上限，`to_chars` 输出偏移和长度 | 检查错误码、消费终点及边界，数字不受全局 locale 影响 |
| 25 并行算法 | 按资源并行计算独立 CRC | `seq` 和 `par` 输出同一份包，坏块的诊断顺序固定 |
| 26 inline 变量 / ODR | 头文件中共享 `inline constexpr` 格式常量及 CRC 表 | 跨翻译单元引用同一个表，检查链接和实体地址 |
| 27 强制拷贝消除 | `BundleReader::open(path)` 直接返回同类型纯右值，由不可复制、不可移动的 Reader 拥有流与游标 | 关闭可选消除后依然能构建，不依赖具名局部变量的 NRVO |
| 28 求值顺序 | 逐字段推进解码器，利用链式成员调用确定写入顺序 | 对偏移、长度使用依次命名的读操作。函数实参之间不假定从左到右 |
| 29 `invoke` / `apply` | 用 `apply` 展开准备任务拥有的参数，用 `invoke` 统一调用注册的报告函数和成员函数 | 延迟运行时路径和选项有效，扩展回调在工作区锁外执行 |
| 30 `byte` / 节点句柄 / `try_emplace` | 二进制编码、别名节点改键、建立目录时惰性构造条目 | 冲突保留原节点。重复 ID 不构造第二份目录条目，传入实参自身仍会求值 |

第 28 课可对照 `index.number(entry.offset).number(entry.size)`。后一次调用先求值成员调用的对象表达式，前一次写入已完成。读取 `offset` 和 `length` 时用两个语句，以明确推进顺序和错误位置。[C++17 草案 · 函数调用的求值顺序](https://timsong-cpp.github.io/cppwp/n4659/expr.call)

`any` 扩展以主程序注册的 C++ 回调为边界。登记函数将产生值的类型与呈现函数配对，报告生成器按值保存可复制的结果。V1 提供行尾统计和大小直方图。扩展报告在产物发布后生成，报告出错时输出诊断，构建结果仍以产物是否成功发布为准。

## 8. 实现顺序与验收

建议把核心控制在约 1,800～2,600 行 C++，另有演示数据、测试和中文阅读指南。采用 `include/assetforge/`、`src/`、`tests/` 和 `data/` 的仓库布局。

| 阶段 | 交付 | 怎么验收 |
|---|---|---|
| 1. 清单与计划 | 多类指令解析、目录校验、依赖闭包和拓扑排序 | 手算示例顺序一致。覆盖前向引用、共享依赖、环路与失效端点 |
| 2. 顺序构建 | 按计划准备字节、写包、读取和验证 | 对照手工计算的 26 字节内容。验证空资源、偏移、截断、损坏索引和坏 CRC |
| 3. 可复现性与并行 | 纯计算阶段支持执行策略，验证器报告坏资源 ID | 重排声明、换源目录并切换执行策略，比较产物全部字节 |
| 4. 工作区和扩展 | 会话重载、配置切换、别名改名、两类扩展报告 | 检查重载失败和别名冲突的回退，用同步点验证快照一致性 |
| 5. 教学收尾 | 课程标记、样例包、预期输出、CTests 和学习指南 | 能从一条清单记录追踪到包内字节，能从一个坏包追踪到明确的错误 |

格式测试既验证编码后再解码，也使用手算偏移的固定样本，避免两边出现同一种错误后碰巧通过。工作区并发测试通过同步点控制重载和读取的先后。比较并行执行策略时记录平台与工具链，先证实输出一致，再统计耗时。
