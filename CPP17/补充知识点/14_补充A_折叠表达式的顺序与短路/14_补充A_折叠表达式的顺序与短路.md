# 补充 14A · 折叠表达式的顺序与短路（C++17）

> 阅读顺序：第 14 课之后；不占每日主线编号。
> 所需标准：C++17 ｜ 独立代码：`14a_fold_sequencing.cpp`。

## 一、底层原理

### 1.1 结合方式不是求值顺序

左折叠和右折叠决定表达式如何加括号；它们不统一规定所有运算符的操作数求值先后。
例如 `(a + b) + c` 先确定表达式树的组合方式，但不能据此说 `a` 对应的副作用一定先发生。
应先展开括号，再看实际使用的运算符规则。

| 实际运算符 | 本节需要记住的规则 |
|---|---|
| 内建 `,` | 左操作数先于右操作数，适合按序执行步骤 |
| 内建 `&&` | 从左侧开始求值，遇到 false 不再求值剩余右侧表达式 |
| 内建 `||` | 从左侧开始求值，遇到 true 不再求值剩余右侧表达式 |
| `+`、`-` 等算术运算符 | 不能仅凭折叠方向推断副作用的先后顺序 |

因此在算术折叠中反复修改同一个对象，不能因为外层有括号就假定安全。
没有明确序列关系的修改可能造成未定义行为。配套代码不执行这种错误演示。

### 1.2 运行时短路不等于实例化短路

`&&` 可以跳过某个合法表达式的运行时求值，但每个展开出来的表达式仍须满足类型规则。
要隐藏不适用于某个类型的成员访问，仍应使用 13A 中的检测和 `if constexpr`，
或者满足相应条件的 trait 惰性实例化。不能期待前一个参数为 false 就让非法调用通过编译。

### 1.3 函数调用还有一条边界

`packed_all(expensive_a(), expensive_b())` 进入函数体之前，两次实参调用已经发生。
函数体里的 `&&` 折叠只能对已得到的值短路，无法撤销实参构造或函数调用。
配套示例只统计它们都执行了，不依赖两次实参调用之间的先后顺序。

## 二、具体语法

### 2.1 用 void 固定内建逗号运算符

```cpp
template <class... F>
void run_each(F&&... steps) {
    (static_cast<void>(std::forward<F>(steps)()), ...);
}
```

每个步骤的结果被转换为 void，避免返回对象的重载逗号运算符介入。
无论步骤返回什么正常结果，都会从左到右调用；某一步抛出异常时，后面的调用不会执行。
空包合法，什么也不做。这里不是把未知顺序的实参调用“重新排序”：
被延迟的操作必须写在传入的可调用对象体内。

### 2.2 用 bool 固定内建逻辑与

```cpp
template <class... F>
bool run_all(F&&... checks) {
    return (... && static_cast<bool>(std::forward<F>(checks)()));
}
```

显式转换确保参与折叠的是 bool，保留内建 `&&` 的短路。
传入闭包本身会先构造，但闭包中的检查动作延迟到折叠求值时调用。
重载的 `operator&&` 不具有内建逻辑与的短路求值语义。

### 2.3 初值同时参与类型推导

`sum_from(initial, values...)` 使用二元左折叠：`(initial + ... + values)`。
空包返回初值；非空包的每次操作仍按相应运算符的转换规则处理。

- 初值为 `0` 时，空包结果为 int。
- 初值为 `0.0` 时，空包结果为 double，后续数值加法从 double 开始。
- 初值为 `std::string{}` 时，可从字符串对象开始拼接字面量。

这不保证任意类型都有合适的 `operator+`，也不自动防止整数溢出。
浮点加法的舍入还可能受括号结合方式影响。

## 三、实际应用与最佳实践

### 3.1 场景：依次执行步骤与按需校验

`run_each` 用于顺序记录日志、执行互相独立的处理步骤；`run_all` 用于前置条件不满足就停止的校验。
示例的步骤只在执行时追加 `A/B/C`：逻辑折叠得到 `false AB`，逗号折叠得到 `ABC`。
这组输出同时验证了顺序和是否跳过后续动作。

### 3.2 区分惰性操作与急切实参

示例最后比较两个调用：传入已计算的 bool 时计数为 2，传入闭包时计数为 1。
选择是否延迟，应依据实际代价和副作用，而非只看函数内部是否写了 `&&`。
更完整的 C++17 求值顺序规则留到主线第 28 课；本节只讨论折叠相关的这几个边界。

## 常见陷阱

1. 把左折叠误认为所有运算符都从左到右求值。
2. 对会重载 `&&` 的对象直接做逻辑折叠，却期待短路。
3. 把昂贵操作作为普通实参执行，再期待函数体阻止它发生。
4. 认为运行时 false 能掩盖一个类型不合法的后续表达式。
5. 随意选择初值类型，导致本来希望的数值精度或字符串重载不匹配。

从 `ModernCPP` 目录执行：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic "CPP17/补充知识点/14_补充A_折叠表达式的顺序与短路/14a_fold_sequencing.cpp" -o run
```

除了预测注释，代码还用运行时检查核对日志顺序和急切、惰性调用次数。

## 练习

1. 将三个步骤的第二个改为 true、第三个改为 false，预测日志和调用次数。
2. 用 `||` 实现 `run_any`，说明其空包结果以及何时停止。
3. 在第二个步骤抛出异常，观察 `run_each` 是否仍会执行第三个步骤。
4. 比较 `sum_from(0, 1, 2)` 和 `sum_from(0.0, 1, 2)` 的返回类型。
