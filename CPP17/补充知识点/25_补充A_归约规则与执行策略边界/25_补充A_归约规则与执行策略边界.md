# 补充 25A · 归约规则与执行策略边界（C++17）

> 阅读顺序为第 25 课之后，不占每日主线编号。
> 所需标准为 C++17。配套代码见 [25a_reduction_contracts.cpp](25a_reduction_contracts.cpp)。

## 一、底层原理

### 1.1 seq 约束执行方式，不把 reduce 变成 accumulate

accumulate 从 init 开始，按输入顺序逐项更新累加值。
reduce 则允许重组和重排归约，即使使用 seq，或者完全没有传执行策略，也不能依赖左折叠。

对 init 为 0、输入为 1、2、3 的减法：

```text
按左折叠：((0 - 1) - 2) - 3 = -6
另一分组：(0 - 1) - (2 - 3) = 0
```

示例显式计算这两种分组，说明结果为什么依赖分组。
它不把某次 reduce(seq, ..., minus) 的实测结果当成标准保证。

要让重组与重排不改变结果，归约操作通常需要满足结合律与交换律。
整数加法也要先保证不会发生有符号溢出；浮点加法一般不满足精确结合律。
需要固定输入顺序时，选择 accumulate 或明确的循环。

### 1.2 使用可合并的统计结果代替共享累加器

示例把每个读数转换成一个 Stats：

```cpp
struct Stats {
    std::size_t valid = 0;
    std::size_t rejected = 0;
    long long total = 0;
};
```

读数 0～100 贡献 `{1, 0, reading}`，其他值贡献 `{0, 1, 0}`。
combine 对三个字段分别相加。这样每次转换只生产自己的结果，
归约只合并传入的值，没有多个回调同时修改外部计数器。

全零 Stats 是这个操作的单位元：与它合并不改变已有结果。
init 只参与整体归约一次，不应理解为每个工作线程都额外加上一份 init。

## 二、具体语法

### 2.1 transform_reduce 的两种回调

```cpp
auto result = std::transform_reduce(
    std::execution::par, first, last, Stats{}, combine, inspect);
```

inspect 将一个元素变成 Stats，combine 把两个 Stats 合成一个 Stats。
代码同时用 seq 与 par 调用，并检查两者都得到合法 4 个、
拒绝 2 个、合计 65。空范围返回全零 Stats，也验证了初值的处理。

示例中的输入很小，所有计数与总和均可表示。
扩展到无界数据之前，需要设计计数和总量的溢出策略；
仅仅换成 long long 并不能自动解决任意规模的溢出。

### 2.2 带 seq 与不带策略，异常规则有区别

| 调用方式 | 元素回调向外抛出异常 |
|---|---|
| `std::for_each(first, last, f)` | 可传播给调用者 |
| `std::for_each(std::execution::seq, first, last, f)` | 调用 std::terminate |
| 使用标准 par 或 par_unseq 策略 | 同样调用 std::terminate |

这里讨论的是元素访问函数向算法外传播的异常。
算法自身申请并行临时资源失败时，标准另有 bad_alloc 的约定。
“加了执行策略就任何异常都绝不传播”和“seq 总能 catch”都不准确。

示例用不带策略的 for_each 验证正常传播。
另设一个默认关闭的独立进程实验，验证带 seq 的版本会进入 terminate handler，
由 handler 明确退出为 86，避免系统崩溃提示或转储干扰练习。

### 2.3 par_unseq 还有同线程交错的限制

par 允许并发调用；par_unseq 还允许同一线程中的未排序交错。
不能因为给共享累加器加上 mutex，就认定它适用于 par_unseq：
互斥锁等向量化不安全操作不能放进这种元素回调。
本例采用不访问外部可变状态的 inspect / combine，回调只做局部整数运算。

## 三、实际应用与最佳实践

这个模式适用于读数校验、日志统计和批量指标汇总：
每条数据形成独立的小统计，再由库合并。
普通业务拒绝用 rejected 计数表达，不需要在元素回调中抛异常。

par 允许实现并行，也允许实现顺序运行。
示例比较的是结果，不测速度、不检查线程数，也不把成功编译当作多线程证据。

本次在 Windows 的 GCC 15.2 与 WSL 的 GCC 13.3 默认配置下验证，
均没有 TBB 头文件，使用了 libstdc++ 的串行后端。
选择 TBB 后端的环境通常还需安装匹配的库并链接 -ltbb。
这些属于工具链实现条件，不能推广成所有 GCC 环境必然缺库或必然并行。
GNU 的旧 `_GLIBCXX_PARALLEL` 模式与 C++17 执行策略也应分别看待。

## 常见陷阱

- 把 reduce(seq) 当成固定左折叠；减法、浮点聚合尤其需要注意。
- 回调捕获外部 sum 并修改；换 par 后可能产生数据竞争。
- 将 noexcept 当作异常处理策略；如果函数实际抛出，noexcept 同样会触发终止。
- 只把无策略调用改成 seq，却忘了同步检查异常处理方式。
- 空范围或额外初值使统计偏移；归约应明确定义单位元与 init 的含义。

## 完整示例

从仓库根目录执行，默认配置不安装额外依赖：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic -pthread "CPP17/补充知识点/25_补充A_归约规则与执行策略边界/25a_reduction_contracts.cpp" -o run.exe
.\run.exe
```

预期输出包括 `left fold: -6`、`another grouping: 0`、
`valid/rejected/total: 4 2 65`、`seq/par agree: true`、
`ordinary exception caught: true`，最后为 `checks: PASS`。
如果本机选择了 TBB 后端，应按该工具链要求在链接命令中添加 -ltbb。

单独开启异常实验：

```powershell
g++ -std=c++17 -DLESSON25A_THROW -Wall -Wextra -Wpedantic -pthread "CPP17/补充知识点/25_补充A_归约规则与执行策略边界/25a_reduction_contracts.cpp" -o policy_throw.exe
.\policy_throw.exe
$LASTEXITCODE # 预期 86，并看到 policy terminate。
```

## 练习

1. 把初值改成 `Stats{0, 0, 100}`，预测空范围与正常范围的结果。
2. 给 Stats 加上“最大合法读数”，设计适合空范围的初值与合并规则。
3. 如果必须生成按输入顺序排列的错误消息，说明为什么不应在 par 回调中直接追加到共享 vector。
