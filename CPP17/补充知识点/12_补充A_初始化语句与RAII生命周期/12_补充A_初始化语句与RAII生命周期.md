# 补充 12A · 初始化语句与 RAII 生命周期（C++17）

> 阅读顺序：第 12 课之后、第 13 课之前；不占每日主线编号。
> 所需标准：C++17、线程库 ｜ 独立代码：`12a_init_raii.cpp`。

## 一、底层原理

### 1.1 作用域不仅决定名字能否使用

`if (init; condition)` 先执行初始化语句，再求值条件。
初始化语句创建的局部对象会存活到整个 `if/else` 结束，因此其析构时间也受该作用域控制。
用一个计数用的 `ScopeProbe` 观察：构造时计数加一，析构时减一。

```cpp
if (ScopeProbe guard(alive); false) {
    // 不执行。
} else {
    // alive 仍是 1：进入 else 不会提前析构 guard。
}
// alive 为 0：整个语句结束，guard 已析构。
```

### 1.2 RAII 把资源释放与作用域绑定

RAII 利用对象构造和析构管理资源。锁守卫、文件流、智能指针可以作为初始化对象，
其清理逻辑随对象离开作用域执行。RAII 是已有机制；C++17 的新内容是
可以把初始化对象直接放到选择语句前面。

条件为 false 不会跳过构造，也不会先释放资源再进入 else。
如果构造本身失败，则不会执行条件与分支；已构造的其他对象按正常异常规则清理。

### 1.3 异常、return 和 break

离开这个对象所属作用域时，正常控制流与异常展开都会调用其析构函数。
`return` 离开所在函数时会清理已经构造的局部对象；`break` 离开 `switch` 时，
会清理该 switch 初始化语句中的对象。
不要把“调用了某个分支”与“守卫已经析构”混为一谈。

## 二、具体语法

### 2.1 条件两侧都持有锁

```cpp
if (std::unique_lock<std::mutex> lock(mutex); allowed) {
    score += 5;
} else {
    // 此处 lock 仍然拥有 mutex。
}
// 此处 lock 已析构并解锁。
```

这里先获得互斥量，再判断 `allowed`。这适用于需要在同一个临界区内完成判断和更新的场景。
如果判断不需要锁保护，应根据真实数据依赖调整代码，避免把额外工作放进临界区。
示例里的 `allowed` 是传入的普通布尔值，重点是演示两分支的锁生命周期。

### 2.2 初始化不是布尔条件

`std::unique_lock` 自身可转换为 bool，但上例真正的条件是分号后的 `allowed`。
二者可以互不相关。使用 `try_to_lock` 时，应显式检查 `lock.owns_lock()`，
不能因为控制流进入某个分支就默认已经获得锁。
配套示例使用阻塞加锁，避免把超时、重试混进本节。

### 2.3 switch 初始化对象覆盖所有 case

配套代码用 `switch (ScopeProbe guard(alive); ++evaluated)` 展示：
守卫先构造，条件执行一次，匹配 case 时守卫仍然存在，离开 switch 后才析构。
初始化对象不属于某一个 case。case 内若再定义局部对象，通常应加花括号，
避免跨越局部初始化的跳转问题。

## 三、实际应用与最佳实践

### 3.1 场景：条件更新共享状态

`add_score` 在同一把锁内决定是否更新积分；调用返回后另一个作用域可以再次获得锁。
构造、分支、异常和析构的验证均在同一线程完成，不依赖时钟阈值或线程调度结果。

### 3.2 保护范围应覆盖真正的数据使用

在持锁作用域中读取数据并返回值快照，可以在解锁后安全处理该快照。
如果返回内部容器的引用，锁守卫已经析构，引用不会继续提供同步保护。
同理，在 else 中做耗时输出或重新获取同一把非递归锁，需要审查是否合理。

## 常见陷阱

1. 认为条件为 false 就不会构造初始化对象。
2. 在 else 中再次获取同一把非递归 mutex，忽略此时旧锁仍被持有。
3. 将 `release()` 误认为解锁；`unique_lock::release()` 只是放弃管理。
4. 在语句结束后使用初始化对象的引用或指针，导致悬空。
5. 把受保护对象的引用返回到解锁之后，误认为 RAII 仍在保护数据。

## 练习

1. 将 true/false 分支交换，预测每个位置的 `alive` 值。
2. 把异常示例改成单独函数中的 `return`，验证返回后计数归零。
3. 为 `add_score` 的两个分支分别记录日志，指出日志发生时是否持锁。
4. 说明为什么返回积分副本与返回 `int&` 对同步保护的要求不同。
