# 补充 20A · 字符串视图的所有权与长度边界（C++17）

> 阅读顺序为第 20 课之后，不占每日主线编号。
> 所需标准为 C++17。配套代码见 [20a_view_boundaries.cpp](20a_view_boundaries.cpp)。

## 一、底层原理

### 1.1 只读视图为什么会跟着变化？

`std::string_view` 不拥有字符。“只读”表示不能通过这个接口修改字符，
并不表示底层数据不可变，也不表示构造时保存了一份内容快照。

```cpp
std::string source = "gate|tail";
std::string_view head{source.data(), 4};
std::string saved{head};
source[0] = 'G'; // 只修改已有字符，不改变缓冲区。
```

此时 `head` 读到 `"Gate"`，`saved` 仍是 `"gate"`。
复制视图只复制借用关系；构造 string 才复制字符并取得独立所有权。
视图常见实现为指针和长度，具体大小和布局由实现决定。

### 1.2 对象还活着，不等于视图仍有效

视图有效需要两个条件：底层字符仍存在，而且原来的地址范围仍可用。
原 string 析构会让视图悬空；扩容等使指针失效的操作也会让旧视图失效。
因此，只检查 string 是否还活着并不充分。

返回视图、把视图放进成员或容器，都要求使用者维护这两个条件。
例如，返回字符串字面量的视图是可行的；返回局部 string 的视图会悬空。
从输入 string 返回子视图，则需要调用者保证输入的存储在后续使用期间一直有效。
异步任务需要独立保存输入时，通常直接持有 string 更容易维护。

## 二、具体语法

### 2.1 指针构造与“指针 + 长度”构造

```cpp
std::string payload{"a\0b", 3};
std::string_view a{payload.data()};                 // size() == 1
std::string_view b{payload.data(), payload.size()}; // size() == 3
```

只传指针时会扫描终止零字符；显式传长度时按给定范围构造，
中间的零字符也是内容。前者要求存在可访问的零结尾字符序列，
后者要求整个指定范围有效。两者都不复制字符。

这也解释了“零拷贝”与“常数时间”的区别：指针构造可能需要扫描，
已经知道长度时应把长度一起传入。

### 2.2 data() 不会把长度交给 C 接口

示例中 `head.size()` 为 4，但 `std::strlen(head.data())` 为 9。
这次调用本身合法：底层完整 string 仍然有效，零字符在 `"Gate|tail"` 的末尾。
问题在于 C 接口不知道视图在第 4 个字符处结束，于是读到了视图之外的后缀。

如果底层范围根本没有零字符，类似调用还可能越界。适配方式取决于接口：

| 接收方约定 | 传递方式 |
|---|---|
| 支持指针与长度 | 同时传 `data()` 与 `size()` |
| 只接收零结尾字符串 | 先 `std::string owned{view};`，再传 `owned.c_str()` |
| 可能保存传入指针 | 另行保证 owned 的寿命覆盖对方的全部使用过程 |

复制到 string 可以补齐末尾终止符，但不能让传统 C 字符串接口识别内嵌零字符：
`"a\0b"` 即使存进 string，`strlen` 仍只看到前面的 `"a"`。

### 2.3 缩短窗口不会改动原字符串

`remove_prefix(n)` 与 `remove_suffix(n)` 只调整视图，要求 `n <= size()`。
`substr` 生成另一个借用视图，也不会延长底层存储的生命周期。
对空视图调用 `front()` 或 `back()` 不合法，裁剪前应先检查范围。

## 三、实际应用与最佳实践

示例处理一行 `"  user=alice  "`：

1. 在局部视图上去掉两端空格。
2. 找到等号，切出 key 和 value，两者都借用原行。
3. 把需要保存的 value 转成 string。

这种方式适合配置解析、日志字段切分和协议文本处理。
解析期间只移动窗口；需要跨越原始输入生命周期的数据再取得所有权。
这里不声称整个业务过程都不分配：最后构造 string 就可能分配内存。

## 常见陷阱

- `std::string_view v = make_string();`：若返回临时 string，分号后 v 已悬空。
- 从 `source.substr(...)` 构造视图：string 的 substr 返回新的临时 string；
  可先构造 `std::string_view{source}`，再调用视图的 substr。
- 把 view 当作内容快照：底层原地变化会反映到视图上，并发访问还需要同步。
- 把视图作为关联容器的键：除了地址有效，还要保证作为键的字符内容不变化，
  否则会破坏容器对哈希或排序的要求。

## 完整示例

在仓库根目录编译运行：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic "CPP17/补充知识点/20_补充A_字符串视图的所有权与长度边界/20a_view_boundaries.cpp" -o run.exe
.\run.exe
```

重点输出为 `view: Gate`、`snapshot: gate`、长度 `4 / 9 / 4`、
内嵌零字符对应长度 `1 3`，最后为 `checks: PASS`。
示例没有解引用失效视图。
