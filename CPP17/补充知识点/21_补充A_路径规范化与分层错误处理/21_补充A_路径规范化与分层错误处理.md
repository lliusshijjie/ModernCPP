# 补充 21A · 路径规范化与分层错误处理（C++17）

> 阅读顺序为第 21 课之后，不占每日主线编号。
> 所需标准为 C++17。配套代码见 [21a_path_and_errors.cpp](21a_path_and_errors.cpp)。

## 一、底层原理

### 1.1 路径字符串相同与“同一个文件”是两回事

`fs::path` 保存路径的表示形式。比较两个 path 的词法表示，
不能替代对实际文件身份的判断。不同路径可能经过 `..`、符号链接或硬链接，
最终指向同一个对象。

| 操作 | 是否查询文件系统 | 解决的问题 |
|---|---|---|
| `p.lexically_normal()` | 否 | 按词法规则消去冗余分隔符、点号等 |
| `fs::canonical(p, ec)` | 是 | 对存在的路径解析符号链接，得到不含点号的绝对路径 |
| `fs::equivalent(a, b, ec)` | 是 | 查询两个路径是否指向同一个文件系统对象 |

例如，`sub/../notes.txt` 可以在不查盘时简化为 `notes.txt`。
但 canonical 需要实际解析路径；示例特意创建 sub 目录，
让原始路径的中间组成部分也存在。遇到符号链接时，纯词法消去 `..`
还可能改变路径实际指向，不能把这两种规范化相互替换。

### 1.2 一次错误码检查只覆盖一次操作

```cpp
std::error_code ec;
auto target = fs::canonical(input, ec);
if (ec) { /* 处理本次失败 */ }

bool same = fs::equivalent(input, target, ec);
if (ec) { /* 处理另一次失败 */ }
```

符合相应约定的成功调用会清除 ec，失败调用会设置 ec。
如果连续调用多次后才检查，后一次成功就可能覆盖前一次错误。
复用 error_code 对象本身没有问题，检查时机才是关键。

错误码重载把文件系统错误交给调用方，但不能由“参数里有 ec”
推出整个调用链绝不抛异常。要查看具体函数的异常约定；
路径构造、容器分配、字符串转换也可能抛异常。

## 二、具体语法

### 2.1 区分“文件不存在”和“查询失败”

`fs::status(p, ec)` 返回 `file_status`。
不存在的路径可以得到 `file_type::not_found`，同时保留对应底层错误。
示例把 `no_such_file_or_directory` 归为预期缺失分支，其他错误仍然报告。

```cpp
auto state = fs::status(missing, ec);
if (ec && ec != std::errc::no_such_file_or_directory) {
    throw std::system_error(ec, "status");
}
// 再根据 state.type() 判断是否为 not_found。
```

读取不到目录也可能来自权限或其他故障。
若一律当成“没有文件”，业务端就失去了诊断依据。

### 2.2 错误返回值不能参与正常统计

`fs::file_size(p, ec)` 失败时返回 `static_cast<std::uintmax_t>(-1)`，
即该无符号类型的最大值。必须先处理 ec，再把有效字节数加入总量。
否则，一次失败就可能让汇总出现巨大数字或无符号回绕。

本例有意查询不存在的 missing.txt，验证错误标记和失败返回值。
目录等非普通文件的 file_size 结果由实现定义，不适合作为统一的失败用例。

### 2.3 遍历有三个分别可能失败的位置

```cpp
fs::directory_iterator it{root, ec}; // 1. 打开目录
// 检查 ec
while (it != fs::directory_iterator{}) {
    bool regular = it->is_regular_file(ec); // 2. 查询条目
    // 检查 ec，再使用 regular
    it.increment(ec);                      // 3. 推进迭代器
    // 再检查 ec
}
```

只把构造器换成 ec 重载，并没有覆盖后续查询与推进。
范围 for 隐式使用 `++it`，不会自动改成 `increment(ec)`。
需要逐步处理错误时，应显式编写循环。

## 三、实际应用与最佳实践

示例读取一个很小的练习目录：普通文件 notes.txt、子目录 sub，
以及一个应当不存在的 missing.txt。程序不改动传入目录。

它先比较路径表示与实际身份，再验证缺失文件的两种查询，
最后收集普通文件名并排序。这个模式可以用于批处理工具：
查询后立即处理错误，在结果有效之后才进入业务统计。

目录遍历不提供内容快照。查询后到使用前，文件仍可能被其他程序修改；
即使某个条目的属性被缓存，也不应当理解为它一直保持最新。

## 常见陷阱

- 用 `a == b` 判断是否为同一个实际文件；需要身份判断时使用 equivalent。
- 先规范化再无条件认定文件存在；词法计算不验证磁盘内容。
- file_size 失败后仍累加返回值；应先检查 ec。
- 只检查迭代器构造，却漏掉属性查询和 increment。
- 要求目录遍历天然有稳定顺序；确定输出应收集后排序。

## 完整示例

从仓库根目录编译，再在系统临时目录创建一份独立练习数据。
练习目录保留供观察，下面的 C++ 程序只读取它。

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic "CPP17/补充知识点/21_补充A_路径规范化与分层错误处理/21a_path_and_errors.cpp" -o run.exe
$demoRoot = Join-Path $env:TEMP ('moderncpp21a-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path (Join-Path $demoRoot 'sub') -Force | Out-Null
[IO.File]::WriteAllText((Join-Path $demoRoot 'notes.txt'), 'ready')
.\run.exe $demoRoot
```

预期包含 `lexical: notes.txt`、`same file: true`、`missing: true`、
`size failed: true`、`file: notes.txt`，最后为 `checks: PASS`。
无参数启动会输出用法并返回 2；查询失败时输出原因并返回 1。
