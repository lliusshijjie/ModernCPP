# 补充 19A · 缺失值与错误的分层建模（C++17）

> 阅读顺序为第 19 课之后，不占每日主线编号。
> 所需标准为 C++17。配套代码见 [19a_decode_layers.cpp](19a_decode_layers.cpp)。

## 一、底层原理

脉冲计时模块可能还没收到记录，也可能收到了损坏的记录。收到并成功解码的记录还允许计数为 0。调用方需要分别处理这些状态。

```cpp
using Frame = std::optional<std::any>;
using Outcome = std::variant<Duration, DecodeError>;
using Decoded = std::optional<Outcome>;
```

外层 optional 描述记录是否到达。输入中的 any 接收扩展模块交来的载荷。通过校验后，业务端拿到一个封闭的结果类型，明确区分时长与错误。

## 二、具体语法

| 输入 | 解码结果 |
|---|---|
| `std::nullopt` | 没收到记录 |
| `Frame{std::in_place}` | 收到记录，内部 any 为空 |
| `Frame{std::any{0}}` | 载荷类型错误，普通 int 与 `PulseCount` 不同 |
| `Frame{std::any{PulseCount{0}}}` | 成功，时长为 0 ms |
| 计数低于 0 或高于 1000 | 计数越界 |

`std::in_place` 让外层 optional 包含一个原位默认构造的 any。这给了“有记录但没有载荷”独立的表达。指针版 `any_cast<PulseCount>` 用于检查实际载荷类型，匹配成功后才能读取计数。

## 三、实际应用与最佳实践

示例将每个 tick 定为 10 ms。解码时先验证 0～1000 的范围，再生成 `Duration`。因此换算结果落在 0～10000 ms。业务端只处理已校验的时长、已知错误和缺失记录，扩展载荷的动态类型集中在 `decode` 内部处理。

错误分支保留了原因。没有记录时调用方可以等待下一帧，类型错误或越界则可以记录具体问题。演示覆盖零值、上下界和正常计数。

## 常见陷阱

- 把“缺失”和“校验失败”都返回为 `nullopt`，会让调用方失去错误原因。
- 用 0 表示无记录会丢掉合法的零值。示例由 optional 的状态表达缺失。
- 把 any 一直传入业务层会让每个读端重复判断动态类型。示例在入口统一转换为 `Duration` 或 `DecodeError`。
