# 第 11 课 · 结构化绑定 structured bindings（C++17）

> 所需标准：**C++17** ｜ 讲解：本文件 ｜ 独立代码：`11_structured_bindings.cpp`

## 一、底层原理

### 1.1 先确定隐藏对象，再按规则引入绑定名

```cpp
auto [a, b] = f();
```

编译器先引入隐藏对象或引用 e，再根据数组、tuple-like、数据成员三种规则引入绑定名。
对于 tuple-like 类型，元素由 `get<I>` 取得，不一定就是 e 的直接成员。
先看 e 是否拥有值对象，再看元素本身是否含有引用：

| 现象 | 原因 |
|---|---|
| `auto& [a, b] = obj;` 改 a 即改 obj | 名字是别名，指向 obj 的成员 |
| `auto [a, b] = obj;` | 从左值复制隐藏对象；引用元素仍可能指向原来的数据 |
| 普通元素的绑定名可取地址、用于 `sizeof` | 操作对应元素；位域不能取地址 |
| C++17 不能直接捕获绑定名，C++20 可以 | C++17 可用 `[copy = a]` 初始化捕获 |

### 1.2 三种可分解的目标

| 目标 | 绑定方式 |
|---|---|
| C 风格数组 | 隐藏对象为数组拷贝（或引用原数组），名字逐元素绑定 |
| tuple-like（tuple/pair 及自定义协议） | 经成员 `get<I>` 或 ADL 找到的 `get<I>` 取元素 |
| struct（全体非静态数据成员、同访问级别、public） | 直接绑定成员，零开销 |

自定义 tuple-like 类型需要合规的 `std::tuple_size`、`std::tuple_element` 特化，
以及成员 `get<I>` 或关联命名空间中的自由 `get<I>`。不要向 `std` 添加新的 `get` 重载。
简单公开成员结构也可以直接按成员分解，无需自定义协议。

### 1.3 解决 C++14 的什么旧问题

| C++14 写法 | 痛点 | C++17 写法 |
|---|---|---|
| `std::tie(x, y) = f();` | 变量要先声明、要可默认构造 | `auto [x, y] = f();` 一行 |
| `p.first / p.second` | 魔法名，语义全靠猜 | `auto [key, value]` 自带语义 |
| `for (auto& kv : m) kv.first` | 同上 | `for (auto& [k, v] : m)` |

## 二、具体语法

```cpp
auto       [a, b] = f();     // 按值初始化隐藏对象；从左值初始化时通常复制
auto&      [a, b] = obj;     // 别名：直接绑定 obj 的成员
const auto& [a, b] = f();    // 延长临时量生命周期 + 只读
auto&&     [a, b] = f();     // 绑右值，同样延长生命周期（推荐默认写法之一）
```

规则细则：

- C++17 中名字个数必须与目标元素数一致，不能省略中间字段。
- `decltype(绑定名)` 有特殊规则：成员分解依据成员声明类型及适用 cv，
  tuple-like 分解依据 `tuple_element<I, E>::type`，不等于 `decltype(get<I>(e))`。
  `decltype((绑定名))` 则按一般表达式规则处理；引用成员不会自动去掉引用。
- struct 情况要求：所有非静态数据成员 public、同一访问级别、非匿名
- `const auto&` 限制对象本身的可写性，但不会把引用元素所指向的数据也变成 const。
- 与 if-init 组合是绝配：`if (auto [it, ok] = m.insert(x); ok) {...}`（第 12 课详述）

## 三、实际应用与最佳实践

### 3.1 场景：map 遍历（头号用例）

```cpp
for (const auto& [key, value] : m) { ... }
```

`.first/.second` 时代一去不返——key/value 自带语义，review 成本骤降。

### 3.2 场景：接收多返回值

`insert` 的 `pair<iterator, bool>`、自定义 `minmax`、tuple 返回——
全部一行解构，不再需要 tie 预声明变量。

### 3.3 最佳实践清单

1. map/unordered_map 遍历一律结构化绑定，禁止再写 `.first/.second`
2. 函数返回 struct（有名字的字段）比 tuple 更好；拿到手后绑定分解
3. 只要读就 `const auto&`；要改就 `auto&`；接函数返回值可用 `auto` 或 `auto&&`
4. C++17 的 lambda 需要绑定值时，可用 `[copy = a]` 初始化捕获；
   引用捕获还必须保证目标对象存活。C++20 起可直接捕获绑定名。
5. 与 if-init 组合写查找-判断一条龙（见第 12 课）

## 常见陷阱

1. **`std::minmax` + 临时实参 = 悬空引用**：`minmax(3, 7)` 返回
   `pair<const int&, const int&>`，引用的是**临时量**；临时量在语句末死亡，
   无论你用 `auto` 还是 `auto&&` 接都悬空——先具名变量再传
2. 以为复制隐藏对象就复制了引用指向的数据；`tuple<int&>` 是反例。
3. 成员访问条件或成员分布不满足成员分解要求，且未提供合规 tuple-like 协议。
4. 在 C++17 中省略某个绑定名；名字个数必须精确匹配。
5. 试图直接按 union 的当前活跃成员进行分解；不能据此绕过分解规则。
6. 将 C++20 的直接捕获绑定名写法当成 C++17 的可移植能力。
