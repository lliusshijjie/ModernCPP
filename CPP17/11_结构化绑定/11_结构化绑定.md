# 第 11 课 · 结构化绑定 structured bindings（C++17）

> 所需标准：**C++17** ｜ 讲解：本文件 ｜ 独立代码：`11_structured_bindings.cpp`

## 一、底层原理

### 1.1 绑定名不是变量，是"隐藏对象的成员别名"

```cpp
auto [a, b] = f();
```

编译器实际生成的形态：先造一个**隐藏对象 e**（存放 f() 的返回值），
然后 `a`、`b` 只是 e 的两个成员的名字——每次使用 `a` 都是在访问 `e` 的成员。
这一条原理解释了全部行为：

| 现象 | 原因 |
|---|---|
| `auto& [a, b] = obj;` 改 a 即改 obj | 名字是别名，指向 obj 的成员 |
| `auto [a, b] = obj;` 改 a 不影响 obj | 隐藏对象是**拷贝** |
| 无法单独取 `&a` 的存储/无法单独 sizeof | 名字不是独立变量 |
| C++17/20 的 lambda 不能捕获单个绑定名 | 同上（C++26 放宽，先记住别踩） |

### 1.2 三种可分解的目标

| 目标 | 绑定方式 |
|---|---|
| C 风格数组 | 隐藏对象为数组拷贝（或引用原数组），名字逐元素绑定 |
| tuple-like（tuple/pair，按 `std::get<I>` 协议） | 经 `get<I>` 取元素 |
| struct（全体非静态数据成员、同访问级别、public） | 直接绑定成员，零开销 |

自定义类型想被分解：按 tuple 协议特化 `std::tuple_size` + `std::get` 即可——
协议是公开的，不要求继承任何东西。

### 1.3 解决 C++14 的什么旧问题

| C++14 写法 | 痛点 | C++17 写法 |
|---|---|---|
| `std::tie(x, y) = f();` | 变量要先声明、要可默认构造 | `auto [x, y] = f();` 一行 |
| `p.first / p.second` | 魔法名，语义全靠猜 | `auto [key, value]` 自带语义 |
| `for (auto& kv : m) kv.first` | 同上 | `for (auto& [k, v] : m)` |

## 二、具体语法

```cpp
auto       [a, b] = f();     // 拷贝进隐藏对象
auto&      [a, b] = obj;     // 别名：直接绑定 obj 的成员
const auto& [a, b] = f();    // 延长临时量生命周期 + 只读
auto&&     [a, b] = f();     // 绑右值，同样延长生命周期（推荐默认写法之一）
```

规则细则：

- 名字个数必须与目标元素数一致；不能跳过不想要的（C++26 才有 `_` 占位符）
- `decltype(绑定名)` 的结果与目标种类有关：struct 情形给成员**声明类型**
  （去引用，`int`）；tuple 情形给 `decltype(get<I>(e))`（带引用，`int&`）——
  但无论哪种，名字在语义上都是别名（示例 ① 已实证）
- struct 情况要求：所有非静态数据成员 public、同一访问级别、非匿名
- 绑定名上的 cv 来自 `auto` 修饰：`const auto& [k, v]` 里 k/v 都是只读
- 与 if-init 组合是绝配：`if (auto [it, ok] = m.insert(x); ok) {...}`（第 12 课详述）

## 三、实际应用与最佳实践

### 3.1 场景：map 遍历（头号用例）

```cpp
for (const auto& [key, value] : m) { ... }
```

`.first/.second` 时代一去不返——key/value 自带语义，review 成本骤降。

### 3.2 场景：接收多返回值

`insert` 的 `pair<iterator, bool>`、自定义 `minmax`、tuple 返回——
全部一行解构，不再需要 tie 预声明变量。

### 3.3 最佳实践清单

1. map/unordered_map 遍历一律结构化绑定，禁止再写 `.first/.second`
2. 函数返回 struct（有名字的字段）比 tuple 更好；拿到手后绑定分解
3. 只要读就 `const auto&`；要改就 `auto&`；接函数返回值可用 `auto` 或 `auto&&`
4. lambda 里要用绑定值：先解构成真变量，或整体捕获隐藏对象不可行——
   直接捕获用到的原始对象（C++20 起可直接捕获绑定名）
5. 与 if-init 组合写查找-判断一条龙（见第 12 课）

## 常见陷阱

1. **`std::minmax` + 临时实参 = 悬空引用**：`minmax(3, 7)` 返回
   `pair<const int&, const int&>`，引用的是**临时量**；临时量在语句末死亡，
   无论你用 `auto` 还是 `auto&&` 接都悬空——先具名变量再传
2. 以为 `auto [a, b]` 拿到的是引用：那是拷贝，改 a 不影响原对象
3. struct 成员非 public 或访问级别不一致 → 无法分解（编译错）
4. 期望"跳过中间字段"：名字个数必须精确匹配，C++26 的 `_` 占位符才解决
5. union 只能绑定一个当前活跃成员，乱绑是未定义行为
6. C++17/20 里 lambda 捕获单个绑定名编译失败——别和普通变量混为一谈
