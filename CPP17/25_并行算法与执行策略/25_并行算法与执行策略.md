## 一、底层原理

### 1.1 执行策略：一个 tag，选择一组重载

C++17 给约 69 个标准算法加了**带执行策略的重载**——策略只是第一个参数
多了一个 tag 对象（空类型），作用有二：

1. **重载选择**：选中的是"允许并行"的那套实现
2. **契约声明**：调用方以此承诺"我的数据在并发元素访问下是安全的"

### 1.2 许可而非强制（permission, not mandate）

`par` 不是命令而是许可：实现可以真的多线程，也可以顺序跑完——
语义必须与顺序版**等价**。所以它是性能提示，不是性能保证；
收益要靠测量，不靠信仰。

### 1.3 三策略 + 异常规则（C++17 全家）

| 策略 | 语义 | 允许的实现方式 |
|---|---|---|
| `seq` | 当前线程顺序 | 仅顺序 |
| `par` | 多线程并行（元素分块） | 并行或顺序 |
| `par_unseq` | 并行 + **向量化/同线程交错** | SIMD 也行 |
| `unseq`（C++20） | 单线程内向量化 | 第 41 课预告 |

**异常规则**：元素函数抛异常时，`seq` 版正常传播；`par`/`par_unseq` 版
**直接 `std::terminate`**——异常不能跨线程飞，标准库选择快速失败。

### 1.4 现实约束：GCC 的 par 后端是 TBB（本机实测）

libstdc++ 的并行算法靠 Intel TBB 实现：**不装 TBB、不链 `-ltbb`，链接阶段
直接失败**（本机已实测：`cannot find -ltbb`）。MSVC 自带后端无需额外依赖。
本课示例因此用 `seq` 实跑、`par` 以注释给出完整启用命令——
"标准写进纸面、落地靠生态"，这是每个工程党都该知道的一课。

### 1.5 顺带到来的新算法（不碰策略也能用）

`transform_reduce`、`reduce`、`for_each_n`、`exclusive_scan` 等**新算法**
与执行策略同批入库——它们顺序调用也完全可用。其中 `transform_reduce`
是并行累加的正解：`for_each` + 共享累加器在 `par` 下是数据竞争，
`transform_reduce` 把"分块归约 + 合并"交给库。

## 二、具体语法

```cpp
#include <execution>
std::sort(std::execution::par, v.begin(), v.end());
std::for_each(std::execution::par, v.begin(), v.end(), f);
std::count_if(std::execution::par_unseq, v.begin(), v.end(), pred);

// 新算法（策略参数可省略 = 顺序执行）
std::reduce(first, last, init);                                     // 纯求和（3 参版在这！）
std::transform_reduce(first, last, init, plus, [](int x){...});     // 变换后归约（无 3 参版）
std::transform_reduce(first1, last1, first2, init);                 // 两范围点积
std::for_each_n(first, n, f);
```

规则细则：

- 策略对象是 constexpr tag，无状态零开销
- 元素函数需满足：可并发调用、无共享可变状态；异常 → terminate（见 1.3）
- `reduce` 的 op 需满足结合律且不对顺序敏感（浮点慎用——顺序不同结果微差）

## 三、实际应用与最佳实践

### 3.1 场景：大数据量清洗/排序/统计（示例 ③-1 的注释即启用路径）

千万级 vector 的 sort/count_if：装 TBB、加 `-ltbb`、把 `seq` 换 `par`
三步完成并行化——不改算法结构。

### 3.2 场景：并行安全的聚合（示例 ③-2）

`transform_reduce` 一行完成"变换 + 求和"，顺序版就是安全的；
升 `par` 只需加策略参数。

### 3.3 最佳实践清单

1. **先测量再并行**：N 小或元素操作便宜时 par 反而更慢（线程分发开销）
2. 元素函数必须无共享可变状态；聚合用 `transform_reduce`，别手写累加器
3. 元素函数不抛异常（par 下 = terminate）；校验逻辑前置到循环外
4. GCC 记得 `pacman -S mingw-w64-ucrt-x86_64-tbb` + `-ltbb`；MSVC 开 `/O2`
5. `par_unseq` 允许向量化与同线程交错——元素间有顺序依赖的代码禁用
6. 浮点归约想可复现：固定 `seq` 或接受微差；`reduce` 不保证求值顺序

## 常见陷阱

1. **`for_each(par)` 里 `++sum`**：教科书级数据竞争（UB）——多线程同时
   读写同一变量且无同步；正解 `transform_reduce`
2. 元素函数抛异常 + `par` → `std::terminate`，不是异常传播
3. 以为加了 `par` 就一定并行/一定更快（见 1.2 与清单 1）
4. GCC 下忘链 TBB：编译通过、**链接报错**（undefined reference / cannot find -ltbb）
5. `reduce` 用不满足结合律的 op（如浮点减法串）→ 结果不可复现
