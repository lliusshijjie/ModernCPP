# 第 09 课 · 语言小件合辑：二进制字面量、数字分隔符、[[deprecated]]（C++14）

> 所需标准：C++14 ｜ 讲解：本文件 ｜ 独立代码：`09_binary_literals.cpp`

## 一、底层原理

### 1.1 二进制字面量 `0b`：又一场"记法"革命

词法层面与 `0x` 十六进制同样处理：lexer 直接算出值，**生成的代码与
十进制写法一字不差**——零成本，纯记法升级。

| 场景 | 旧写法 | C++14 写法 |
|---|---|---|
| 位掩码 | `0xF0` 或 `240` | `0b1111'0000` |
| 权限位 | `6`（谁知道是什么） | `0b110`（读-写一眼可见） |
| 协议字节 | `0xAA, 0xBB` | `0b1010'1010, 0b1011'1011` |

写位标志的人（协议解析、寄存器操作、权限系统）等这一等号等了二十年。

### 1.2 数字分隔符 `'`：纯词法、零语义

分隔符在 **lexer 阶段被直接丢弃**——值一个比特都不变，它只服务于人眼：

```cpp
static_assert(1'000'000 == 1000000, "");
static_assert(0xFF'FF == 65535, "");
static_assert(0b1111'0000 == 0xF0, "");   // 组合拳：按 nibble 分组
```

数零是 bug 温床：`10000000` 是 10⁷ 还是 10⁸？`10'000'000` 不用数。

### 1.3 [[deprecated]]：编译器替你发的"迁移引导"

API 演进的三难：直接删（破坏用户）/ 不吭声（烂摊子）/ 写注释（没人看）。
`[[deprecated]]` 走第四条路——**标注在声明上，编译器在每个"使用点"发警告**
（定义点不发），消息字符串直接给出替代方案：

```cpp
[[deprecated("use new_calc() instead; removed in v3")]]
double old_calc(double x);
```

调用方一编译就收到可执行的迁移指引。属性不改变任何语义，
只影响诊断——这是 C++11 属性机制第一个深入人心的标准化应用。

## 二、具体语法

### 2.1 字面量与分隔符

```cpp
0b1010'1010        // 0b/0B 前缀，数字只能 0/1
1'000'000'007      // 分隔符只能夹在两个数字之间
0xAA'BB'CC'DD      // 所有进制、浮点、甚至 UDL 前都可用
```

规则细则：`0b'101`、`0b101'`、`101'`（开头/结尾/紧贴前缀）都非法。

### 2.2 [[deprecated]]

```cpp
[[deprecated]] void f();
[[deprecated("msg")]] void g();     // 可标注：函数/类/变量/枚举值/命名空间/特化
```

规则细则：

- 警告由 `-Wdeprecated` 触发，**GCC 默认开启**——零配置生效
- 定义不警告，使用才警告 → 库自身可以带着旧符号正常编译发布
- 想屏蔽库内部的调用刷屏：`#pragma GCC diagnostic push/ignored/pop` 包住

## 三、实际应用与最佳实践

### 3.1 场景：API 演进生命周期

标记 `[[deprecated("use X instead")]]` → 下一个大版本用户按警告迁完 →
再删旧实现。警告是**边编译边出现**的迁移清单，比 changelog 靠谱。

### 3.2 场景：位标志与协议字段（示例 ③）

权限位用 `0b100/0b010/0b001` 定义，合成值一眼可读；
报文用 `0xAA'BB'CC'DD` 按字节分组，拆位直接 `>> 16`。

### 3.3 最佳实践清单

1. 位掩码一律 `0b` + 分隔符按 nibble/字节分组
2. 5 位以上的数字都用分隔符（`1'000'000'007` 这类常数即刻可读）
3. 废弃 API 必须带消息指向替代品；删除前至少留一个发布周期
4. `[[deprecated]]` 是给调用方看的活文档，比注释强一个数量级
5. 二进制位数写错编译器不管（`0b100` vs `0b0010`）——配 `static_assert` 锁值

## 常见陷阱

1. 分隔符只能在数字之间：`0b'101`、`0b101'`、`'101` 全部非法
2. 分隔符是 `'` 不是 `,`：`1,000` 是逗号运算符表达式（值 0）！
3. 库内部调用废弃函数也会刷警告——用 diagnostic push/pop 精确屏蔽，
   别全局 `-Wno-deprecated`（会把用户调用方的警告也关掉）
4. 消息字符串只在编译期出现，别往里塞运行期信息
5. `0b100` 和 `0b0010` 值不同——位定义抄写错误编译器不查，
   关键标志位配 `static_assert` 或对拍用例
