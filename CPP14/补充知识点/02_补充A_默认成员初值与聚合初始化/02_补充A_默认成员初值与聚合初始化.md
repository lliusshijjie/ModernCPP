# 补充 02A · 默认成员初值与聚合初始化（C++14）

> 阅读顺序：第 02 课之后、第 03 课之前；不占每日主线课编号。
> 所需标准：C++14 ｜ 独立代码：`02a_aggregate_initialization.cpp`

## 一、底层原理

### 1.1 C++14 改的是聚合资格

默认成员初值在 C++11 已经存在，例如 `int retries = 3;`。但在 C++11 中，
这样的类不满足聚合的定义。C++14 放宽了这项限制：只要其他条件满足，
带默认成员初值的类仍然可以使用聚合初始化。

```cpp
struct Config {
    int retries = 3;
    int timeout_ms = 100;
    bool trace = false;
};

Config a{};             // 3, 100, false
Config b{5};            // 5, 100, false
Config c{2, 250, true};  // 2, 250, true
```

这里没有为三种参数组合分别写构造函数。编译器按照成员的声明顺序，
把花括号中的元素分配给各成员，再处理未显式提供的成员。

### 1.2 省略成员不等于所有成员都清零

处理每个未显式初始化的成员时：有默认成员初值就使用它，否则从空初始化列表
初始化。对于本课的普通整数、布尔成员，后者分别得到 `0`、`false`。
引用成员不能靠省略自动获得一个可绑定对象。

显式提供的值会覆盖对应的默认成员初值；默认初值还可以读取先前已初始化的成员：

```cpp
struct Limits {
    int base = 10;
    int doubled = base * 2;
};
Limits x{7};             // base=7, doubled=14
Limits y{7, 99};         // base=7, doubled=99
```

## 二、具体语法

### 2.1 C++14 中的聚合条件

本课讨论的类不能有用户提供的构造函数、基类、虚函数或私有/受保护的非静态数据成员。
默认成员初值本身不再取消聚合资格。其他标准版本的条件有所变化，不能直接套用。

`Config x{5};` 与 `Config x = {5};` 都可用于这里的聚合。
花括号初始化还会检查窄化转换，例如 `Config bad{2.5};` 非法。

### 2.2 与 constexpr 的关系

```cpp
constexpr Config defaults{};
constexpr Config custom{5};
static_assert(defaults.timeout_ms == 100, "default timeout");
static_assert(custom.retries == 5, "explicit value wins");
```

满足常量表达式要求时，聚合初始化也可以用于编译期对象；它不要求先声明
一个用户提供的 `constexpr` 构造函数。默认成员初值若依赖运行期函数，
对应初始化就不能因此自动变成常量表达式。

### 2.3 与后续语法的边界

- C++14 按位置填写成员，不能写 `Config{.retries = 5}`；指定初始化器是 C++20 内容。
- `std::is_aggregate` 是 C++17 标准库工具，本课不使用它验证 C++14 代码。
- `Config x;` 与 `Config x{};` 不应普遍视为等价；没有默认初值的标量成员，
  在前一种写法下可能未初始化。

## 三、实际应用与最佳实践

### 3.1 场景：带默认值的选项结构

用聚合表达简单配置：调用方只覆盖前几个成员，其他成员保留合理默认值。
嵌套配置也可以显式分层填写，例如 `WorkerOptions{{4, 200, true}, 6}`。

这适合成员少、顺序清晰、没有复杂不变式的值类型。成员很多或者含义容易混淆时，
先创建 `Config config{};`，再按成员名称赋值，通常比长串位置参数更容易维护。

### 3.2 需要校验时使用构造函数或工厂

聚合允许调用方直接提供各成员，不能替你保证“重试次数非负”等业务规则。
如果对象必须始终满足强约束，应使用构造函数、工厂或封装成员，
不要为了保留聚合资格牺牲对象的不变式。

## 常见陷阱

1. 把“默认成员初值”误认为 C++14 才出现；新增的是它与聚合资格的组合。
2. 在成员中间插入字段后，旧的按位置初始化可能改变含义；修改公共配置结构要检查调用点。
3. 把 `Config{}` 与任意类型的“内存全部清零”混为一谈；初始化遵循成员类型的规则。
4. 给类添加用户提供的构造函数后，仍按原来的聚合成员顺序传参。

## 练习

1. 增加一个默认值为 `8` 的 `max_jobs` 成员，预测已有三种初始化的结果。
2. 给 `Limits` 的 `doubled` 显式传入 `0`，解释为什么不会执行 `base * 2`。
3. 给配置增加必须满足的业务约束，比较直接聚合初始化与工厂函数的适用范围。
