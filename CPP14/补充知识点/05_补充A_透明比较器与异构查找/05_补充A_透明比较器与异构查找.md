# 补充 05A · 透明比较器与异构查找（C++14）

> 阅读顺序：第 05 课之后，接着阅读补充 05B；不占每日主线课编号。
> 所需标准：C++14 ｜ 独立代码：`05a_heterogeneous_lookup.cpp`

## 一、底层原理

### 1.1 查找不一定需要构造完整的键对象

在 `std::map<std::string, int>` 中调用 `find("alice")`，默认比较器是
`std::less<std::string>`，查找接口接收 `key_type`，需要临时构造一个 `std::string`。
字符串很短时不一定分配堆内存，但临时对象的构造仍然存在。

C++14 可以让查找直接使用可与键比较的其他类型：

```cpp
std::map<std::string, int, std::less<>> scores{{"alice", 90}};
auto it = scores.find("alice"); // 用 const char* 查找，无须临时 std::string
```

这叫异构查找：容器存一种键，查询可以使用另一种类型。

### 1.2 std::less<T> 与 std::less<> 的区别

`std::less<int>` 的参数类型固定为 `int`；`std::less<>` 对应 `std::less<void>`，
调用运算符自身是模板，可以保留两个参数各自的类型。
类似的透明函数对象还包括 `std::greater<>`、`std::equal_to<>` 等。

例如比较 `2` 和 `2.5`，`less<int>` 会先把后者转换为 `int`；
`less<>` 则可以直接进行混合类型比较。异构不代表所有类型组合都合法，
底层比较表达式本身必须有意义。

### 1.3 is_transparent 是启用协议

比较器中的嵌套类型 `is_transparent` 告诉有序关联容器：允许启用异构查找重载。
它的具体类型不重要，通常写 `using is_transparent = void;`。

这个标记不负责生成比较逻辑。自定义比较器仍须提供键与查询值之间需要的比较，
并与键之间的排序规则保持一致。

## 二、具体语法

### 2.1 标准比较器

```cpp
std::set<std::string, std::less<>> names{"alice", "bob"};
auto found = names.find("bob");
auto lower = names.lower_bound("b");
```

C++14 的有序关联容器 `map`、`set`、`multimap`、`multiset` 支持相应的
`find`、`count`、`lower_bound`、`upper_bound`、`equal_range` 异构查找重载。

不要把这个列表扩展为异构 `erase`，也不要直接套用到 `unordered_map`：
无序容器的标准异构查找属于 C++20，关联容器的异构擦除属于 C++23。

### 2.2 按一个字段查找完整对象

配套示例在 `set<Product, ById>` 中存储完整商品，但允许 `find(20)` 按 ID 查询。
比较器提供三个重载：

```cpp
using is_transparent = void;
bool operator()(const Product& a, const Product& b) const;
bool operator()(const Product& a, int id) const;
bool operator()(int id, const Product& b) const;
```

三个重载都只比较 ID，避免为了查询而临时构造一个含名称等字段的 `Product`。
跨类型比较的两个方向都要考虑；不能仅凭一次查找碰巧成功就认为契约完整。

## 三、实际应用与最佳实践

### 3.1 场景：名称索引与 ID 索引

配置表、命令表、缓存索引经常收到 `const char*` 查询值，可以使用透明比较器。
如果存储的对象很大，而排序只由一个字段决定，按字段类型查询更能体现价值。

容器采用什么排序，就应使用同一套逻辑定义查询等价关系：
`!comp(key, query) && !comp(query, key)`。
不要让键与键比较按 ID，而键与查询值比较却按名称。

### 3.2 保持所有权与比较语义清晰

容器仍然持有原来的键对象；异构查找没有把存储改成字符串指针，也不延长查询对象
的生命周期。`std::less<>` 对两个裸字符指针的比较也不能被当成字符串内容比较；
本课的字符串查找之所以按内容比较，是因为比较的一方为 `std::string`。

## 常见陷阱

1. 只把 `find` 的实参换成 `const char*`，却仍使用默认的非透明比较器。
2. 只添加 `is_transparent`，没有提供合法且一致的跨类型比较。
3. 在有序容器中使用不满足严格弱序的比较规则，破坏容器要求。
4. 把避免临时字符串等同于一定避免堆分配；小字符串本来就可能没有堆分配。
5. 在 C++14 示例中引入 `std::string_view`；该类型属于 C++17。
