# 补充 07A · 转发返回值与代理对象（C++14）

> 阅读顺序：第 07 课之后、第 08 课之前；建议先完成补充 03A。
> 所需标准：C++14 ｜ 独立代码：`07a_return_types_and_proxies.cpp`

## 一、底层原理

### 1.1 decltype(auto) 保留推导规则，不保证得到引用

第 07 课已经演示 `vector<int>::operator[]` 的引用返回。
但不是所有下标表达式都产生 `T&`。`vector<bool>` 的可写下标返回代理对象，
它保存如何访问某个位的信息，并通过赋值运算符修改该位。

```cpp
std::vector<bool> bits{false, true};
decltype(auto) proxy = bits[0]; // vector<bool>::reference，代理对象的值
bool snapshot = bits[0];       // 转换为独立的 bool 值
```

`bits[0]` 是代理类型的纯右值，所以这里推导出的不是代理类型的 `&&`。
`auto proxy = bits[0]` 同样会得到代理对象；“auto 按值”也不等于已经取得独立的布尔快照。

### 1.2 代理对象与真实引用都依赖原对象

修改代理可以修改原位；修改原位也会影响随后通过代理读取到的值。
代理不是独立的 `bool`。容器销毁或相关操作使引用失效之后，不能再使用该代理。

同理，返回 `T&`、`const T&` 或 `T&&` 不会自动延长被引用对象的生命周期。
`decltype(auto)` 能保留类型信息，不能修复悬空对象。

### 1.3 std::move 本身没有移动资源

```cpp
std::string text = "alive";
decltype(auto) alias = std::move(text); // string&&，只绑定引用
```

这里没有调用移动构造函数，也没有把资源交给另一个字符串。
只有后续初始化、赋值或函数调用实际选择了移动操作时，才会发生相应的移动。
真正移动后的源对象状态要看类型契约，不能统一假定“失效”或“必为空”。

## 二、具体语法

### 2.1 用左值参数限制返回引用的下标封装

```cpp
template <class Container>
decltype(auto) element(Container& c, std::size_t index) {
    return c[index];
}
```

这个接口接受左值容器：普通 `vector<int>` 返回 `int&`，const 容器返回 `const int&`，
`vector<bool>` 返回代理对象。它不能接收临时容器，减少返回值立即失去宿主的风险。
调用方仍须满足下标有效、容器存活、未发生相关失效操作等前提。

### 2.2 return x 与 return (x)

当 `x` 是普通局部整数时：

```cpp
decltype(auto) value() { int x = 7; return x; }   // int，按值返回
// decltype(auto) bad() { int x = 7; return (x); } // int&，离开函数即悬空
```

未加括号的名字和成员访问有特殊的 `decltype` 规则。
`decltype(auto)` 会使用这些规则；它不是无条件把表达式推导为引用。
因此，把工厂的 `auto` 改为 `decltype(auto)` 之后，返回类型是否变化，
必须检查真实的 return 表达式，不能仅凭关键字判断。

### 2.3 尾置返回类型仍有用途

```cpp
template <class T>
auto size_or_zero(const T& value) -> decltype(value.size()) {
    return value.size();
}
std::size_t size_or_zero(...) { return 0; }
```

如果 `T` 没有 `size()`，模板声明中的替换失败可以排除该候选，选择兜底重载。
如果改成从函数体推导 `auto` 返回类型，`return value.size();` 的实例化错误
不会因此自动变成 SFINAE。`decltype(auto)` 返回类型同样需要考虑这一点。

## 三、实际应用与最佳实践

### 3.1 先决定接口语义，再选择返回类型

| 想要的接口 | 可选写法 | 需要检查 |
|---|---|---|
| 独立的布尔快照 | 显式 `bool` | 是否已经转换并脱离代理 |
| 保留被调用表达式的类型 | `decltype(auto)` | 代理、引用及对象生命周期 |
| 明确只返回引用 | 明确的引用类型或 `auto&` | 表达式是否确实可绑定 |
| 返回表达式参与候选筛选 | `auto ... -> decltype(expr)` | 替换是否处于直接上下文 |

### 3.2 使用类型断言记录契约

配套代码用 `std::is_same<decltype(...), Expected>::value` 检查三个下标封装结果，
并用输出演示代理与快照的区别。类型推导规则本身稳定，
不要依赖编译器打印出来的内部代理类型名称作为跨实现契约。

## 常见陷阱

1. 把纯右值代理推导为代理类型的 `&&`。
2. 用 `auto` 接住代理之后，以为已经与原容器没有关系。
3. 返回 `std::move(local)` 并使用 `decltype(auto)`，得到指向局部对象的悬空右值引用。
4. 把模板函数体中的非法成员访问当成可以自动忽略的替换失败。
5. 为了减少字符而一律改用 `decltype(auto)`，却没有检查生命周期和重载行为。

## 练习

1. 对比 `auto`、`decltype(auto)`、`bool` 接住 `bits[0]` 时的类型和赋值效果。
2. 尝试让 `element` 接收临时容器，解释该接口为什么拒绝这次调用。
3. 分别从局部变量、全局变量和函数调用返回值，判断增加括号是否会改变返回类型。
4. 给 `size_or_zero` 添加一个普通整数调用，说明模板候选退出的位置。
