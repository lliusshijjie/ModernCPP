# 第 58 课 · if consteval、static operator()、多维下标（C++23）

> 标准：C++23；代码：`58_language_misc.cpp`；示例用 print，本机链接 `-lstdc++exp`。
> 前置：第 40 课常量求值、第 52 课显式对象参数、第 55 课 mdspan。

## 一、底层原理

### 1.1 if consteval：按常量求值语境选择路径

```cpp
constexpr int count_bits(unsigned x) {
    if consteval {
        int n = 0;
        while (x) { n += static_cast<int>(x & 1u); x >>= 1; }
        return n;
    } else {
        return std::popcount(x);
    }
}
```

`if consteval` 没有括号条件，两侧有语句时都必须是花括号复合语句。
在 manifestly constant-evaluated 的语境中选择真分支，否则选择 else。
普通调用即使被优化器折叠，也不因此变成语言意义上的常量求值。
示例两条路径计算同一结果；`popcount` 本身已支持 constexpr，这里只是演示分派。

与 `if (std::is_constant_evaluated())` 的重要区别是：真分支构成 **immediate function context**，
可以将外层参数用于立即函数调用：

```cpp
consteval unsigned immediate_plus_one(unsigned x) { return x + 1; }
constexpr unsigned plus_one(unsigned x) {
    if consteval { return immediate_plus_one(x); }
    else { return x + 1; }
}
static_assert(plus_one(41) == 42);
```

这不把参数 x 自动变成可初始化任意 constexpr 局部变量的常量表达式。
两个分支仍须满足语法和类型规则，不具备 `if constexpr` 在模板实例化时丢弃分支的机制。

### 1.2 is_constant_evaluated 仍然有效

`if (cond && std::is_constant_evaluated())` 是合法表达式，短路不引入 UB；
不要将它和 `if constexpr (std::is_constant_evaluated())` 混淆。
后者的条件本身要求常量求值，所以该查询为 true，通常不符合期望的运行期分派。

`is_constant_evaluated()` 没有被本特性废弃，适合需要布尔表达式的场合；
需要 C++20 兼容时也可以继续使用。`if !consteval`（或 `if not consteval`）
先写非常量求值路径，后面的 else 对应常量求值路径。

### 1.3 static operator()：没有隐式对象参数

```cpp
struct Square {
    static constexpr double operator()(double x) { return x * x; }
};
Square s;
s(1.5);
Square{}(2.5);
auto pf = &Square::operator();               // 普通函数指针 double(*)(double)
```

C++23 允许静态调用运算符，也允许静态下标运算符。
静态成员没有 this，不能直接访问某个实例的非静态成员；但类本身仍可有状态，
函数也可访问全局/静态状态或通过显式参数访问对象，并非“天然纯函数”。
`static`、`constexpr`、`consteval` 是不同概念。非静态 operator() 早就可以 constexpr；
static 不保证调用立即求值，也不保证比优化后的非静态函数对象更快。
`obj(args)` 中的 obj 表达式仍会求值，因此其中的副作用不会被静态调用规则取消。

## 二、具体语法：多参数 operator[]

```cpp
struct Mat {
    double data[4]{};
    double& operator[](std::size_t r, std::size_t c) {
        return data[r * 2 + c];              // 本例前提 r,c 均小于 2
    }
};
Mat m;
m[1, 0] = 30;
```

C++23 放开下标运算符的参数数量，可表达零参、多参或参数包；
`std::mdspan` 使用的正是 `m[r,c]`，不是标准外的圆括号下标。
重载可自行检查边界、抛异常或定义不同语义；语言不会自动为它加入检查。

内建数组/指针仍只接受一个下标，`vector` 也没有双参重载。
`raw[1, 2]` 在标准 C++23 中不合法，不能把 GCC 可能接受的兼容扩展当作标准语义。
更早版本中它是 `raw[(1,2)]`，C++20 已弃用顶层逗号写法。
显式 `raw[(f(), index)]` 仍是单个逗号表达式参数，保留左侧副作用并取右侧为索引，
不是多维访问。

## 三、实际应用与最佳实践

常量求值分支可使用可移植实现，运行期分支可调用平台实现；两条路径应满足相同的业务契约。
原示意中把 sqrt 的常量路径写成 0 或 1 会得到不同数学结果，不能当作正确的双路径数值算法。
当前示例改为结果一致的位计数，并单独演示立即函数上下文。

无状态策略对象可以考虑 static operator()，但不必为了 constexpr 或未经测量的 this 开销机械迁移。
矩阵下标则应在类接口中约定维度、布局和越界行为；多参数只是调用语法，不自动带来形状知识。

## 常见陷阱

1. 真分支可以在源码中出现非 constexpr 操作；只有实际常量求值执行到它们时，才可能使表达式不再是常量表达式。
2. `if consteval` 不自动使整个函数成为 consteval；运行期路径仍能执行。
3. 在真分支内写 `constexpr auto y = x` 不会因 x 是函数参数就自动合法。
4. static operator() 不能 virtual，也不能带成员函数的 cv/ref 限定；同参数列表的静态/非静态版本不能靠 static 区分重载。
5. 不能把 `is_constant_evaluated()` 的合法短路条件诊断成 UB，或声称它已退役。
6. `m[r,c]` 和 `m[(r,c)]` 是不同参数列表，误加括号会改变重载选择。

## 练习

1. 对相同输入分别用 static_assert 和普通调用检查 count_bits，两条路径结果应一致。
2. 用普通 if(is_constant_evaluated()) 调用带参数的立即函数，比较预期编译错误；再换成 if consteval。
3. 检查静态 operator() 的函数指针类型；用带计数副作用的对象表达式验证它仍被求值。
4. 给三维下标加入明确的边界检查，对合法下标与越界异常分别验证，不运行越界 UB。
