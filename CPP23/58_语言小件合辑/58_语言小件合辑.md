## 一、底层原理

### 1.1 if consteval：编译期检测的语法化收编

C++20 的 `std::is_constant_evaluated()` 库函数有两个毛病：
写在嵌套语境会被"顺手用错"（如 `if (x && is_constant_evaluated())`
在运行期分支误判）、且它是**函数调用形态**——不像语言关键字那样
被规则保护。C++23 的 `if consteval { } else { }`（P1937）：

- 分支里**只能**是"当前是否常量求值"这一件事，误用空间被语法关死
- else 分支对应"运行期"——比"取反判断"直白
- 配合 consteval 函数（第 40 课）形成完整工具箱：
  **"必须编译期"用 consteval，"双路径分派"用 if consteval**

典型应用：同一个算法，编译期走保守实现（不依赖 libm/浮点宿主差异），
运行期走快实现（示例 ① 的 safe_sqrt）。

### 1.2 static operator()：函数对象去掉 this

零状态的函数对象（策略、定制点）每次调用都背着 `this`——
虽然无状态时 this 无用，但存在性让它**不能直接出现在**
不允许 this 的语境。C++23（P1169）允许 `static operator()`：

- 无 this、无捕获语义、天然无状态
- 调用方式不变：`obj(args)` / `Type{}(args)` 都行
- **可以 constexpr**（更早的 static 成员函数也能，但 operator()
  此前必须非 static——状态与可调用性被强行绑定）
- 与 deducing this（第 52 课）互补：那边是"self 显式化"，
  这边是"self 根本不存在"

### 1.3 多维 operator[]：迟到四十年

C++98 起 `operator[]` 只准一个参数——矩阵只能 `m[{r,c}]`（包裹）
或 `m(r,c)`（函数调用，mdspan 的选择，第 55 课）。
C++23（P2128）放开为**多参下标**：`m[r, c]` 语义化。

同一版本里编译器也开始警告**顶层逗号下标**（`raw[1, 2]` 是
`raw[(1,2)]` = `raw[2]` 的百年老坑，`-Wcomma-subscript`）——
新语法进来、老陷阱显形，一体两面。

## 二、具体语法

```cpp
constexpr double safe_sqrt(double x) {
    if consteval {                    // 编译期分支
        return conservative(x);
    } else {                          // 运行期分支
        return std::sqrt(x);
    }
}

struct Square {
    static constexpr double operator()(double x) { return x * x; }
};
Square{}(2.5);                        // 6.25（无需实例状态）

struct Mat {
    double m[4];
    double& operator[](std::size_t r, std::size_t c);        // 多参下标
    const double& operator[](std::size_t r, std::size_t c) const;
};
Mat a;
a[1, 0] = 30;                         // 直观二维访问

// raw[1, 2]（未重载类型）：逗号表达式陷阱，编译器警告
```

规则细则：

- `if consteval` 分支内**不能**调用"只能在运行期执行"的东西
  （如 I/O）——分支语境本身即编译期
- 复合版 `if !consteval` 合法（"仅运行期"分支）
- static operator() 不能是 virtual；**同类型内 static 与非 static
  operator() 不能同签名并存**
- 多参 operator[] 的参数数量、类型自由（三维 `m[i,j,k]` 也行）
- 下标语义完全由重载定义——**不查边界**（同单参版老规矩）
- `raw[1, 2]` 的逗号警告只在"顶层逗号"时发；`raw[(1,2)]`
  （显式括号）不警告——但同样是取 raw[2]

## 三、实际应用与最佳实践

### 3.1 场景：编译期/运行期双优算法（示例 ①）

查表、数值计算在编译期常量折叠（第 44 课），运行期用平台优化
指令——同一份源码两个世界各取最优。`if consteval` 是这类代码的
标准分派器。

### 3.2 场景：策略对象零开销化（示例 ③）

`ByTwice{}`、`BySquare{}` 这类策略：static operator() +
模板/泛型形参传递——无 this、可内联、可 constexpr，
比函数指针与带状态的 lambda 都更"类型即策略"。

### 3.3 最佳实践清单

1. 新代码双路径一律 `if consteval`；库函数版冻结退役
2. 零状态函数对象的 operator() 默认加 static（意图明确 +
   constexpr 通畅）
3. 多维访问的类型重载多参 []；与 C 接口互操作时留意逗号陷阱
4. 打开 `-Wcomma-subscript`（随 -Wall）清理存量逗号下标
5. 边界检查自理：多维 [] 与单参 [] 一样不检查越界

## 常见陷阱

1. **if consteval 的分支里写运行期操作**（I/O、锁、时钟）：
   编译期分支根本无法求值——static_assert/常量语境一调即报错；
   这不是限制是提醒：分派要彻底
2. static operator() 与非 static 同签名并放 → 编译错；
   需要状态的版本就别 static
3. `m[1, 2]` 在**没有多参重载**的类型上仍走逗号老路——
   多维 [] 是"你重载了才有"，不是语言自动给
4. 以为多参 [] 有边界检查：没有——越界照旧 UB（对照第 55 课）
5. `if !consteval` 写成 `if consteval` 手抖反义——
   复合条件的可读性慎重，两分支分开写更稳
6. is_constant_evaluated() 旧代码迁移：注意它出现在
   `if (cond && is_constant_evaluated())` 里是**未定义行为的
   温床**（条件短路语境），if consteval 结构性根除
