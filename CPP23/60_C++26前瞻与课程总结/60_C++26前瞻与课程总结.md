# 第 60 课 · C++26 前瞻与课程总结（C++23 → C++26）

> 总结示例：`60_outlook.cpp`，按 C++23 编译。
> 前瞻示例：`60_cpp26_glimpse.cpp`，按 C++26 编译。
> 本机 GCC 15.1.0 的 print 示例链接 `-lstdc++exp`；选择标准模式不等于实现全部特性。

## 一、底层原理：四个标准的能力积累

| 标准 | 本课程代表内容 |
|---|---|
| C++14 | 泛型 lambda、constexpr 增强、变量模板与 integer_sequence |
| C++17 | 结构化绑定、if constexpr、CTAD、optional/variant/any/string_view |
| C++20 | concepts、ranges、比较、format、span、jthread、协程、constexpr 容器 |
| C++23 | print、expected、显式对象参数、ranges::to、generator、mdspan、flat 容器 |

这些能力分别解决表达、约束、资源管理与组合问题，不能仅凭标准更新就推断旧接口过时。
constexpr/consteval 能把适合预先完成的计算从运行期移到常量求值阶段，不是把编译期计算搬回运行期。

### 1.1 一条管道串联课程

`generator（54）→ filter/take（33）→ ranges::to（53）→
expected（50）→ print/范围格式化（49/59）`。

`first_even_squares(3)` 返回 `[4, 16, 36]`，输入 0 返回错误。
平方序列在相乘之前检查 int 的表示范围；参数 n 也先限制为可提供的偶数平方数量，
再转成 take 所需的有符号差值类型。不能让超大 size_t 隐式转换为负数或让生成器先有符号溢出。

返回 expected 只说明业务错误通过值传递；分配 vector/string、协程帧等仍可能抛异常。
示例不宣称 noexcept，也不宣称所有错误都已变成 expected 的错误分支。

## 三、C++26 前瞻与下一步

### 3.1 本机 GCC 15.1 可验证的两项语言特性

- 包索引 P2662：`Ts...[I]` 取类型包中的类型，`args...[I]` 取表达式包中的元素。
  I 必须是有效的常量索引；示例的首项函数要求包非空，按值参数还会复制/移动参数。
  返回声明为 auto 时通常按值返回，并不是通用的引用保持工具。
- 带原因的删除函数 P2573：`void f(double) = delete("reason")`。
  删除的重载仍参与重载决议；选中后程序不合法，原因可出现在诊断中。
  本例拒绝 double 重载，不代表对所有非 int 类型都严格拒绝，也不检查端口数值范围。

### 3.2 已纳入 C++26 的方向，与本机支持分开看

| 设施 | 解决的问题 | 本课说明 |
|---|---|---|
| 反射 P2996 | 编译期查询程序实体，结合生成与拼接 | 不是任意运行期对象的动态反射 |
| 契约 P2900 | 前后条件及契约断言 | 有不同求值/检查语义，不能承诺所有检查总执行 |
| std::execution P2300 | sender/receiver 异步操作组合 | 与 C++17 同命名空间的执行策略不是同一套能力 |
| hazard pointer / RCU | 并发对象的安全回收 | 不是普通智能指针替换，也不保证所有操作均无锁 |
| inplace_vector P0843 | 对象内嵌存储、容量固定、大小可变 | 对象可在栈、堆或其他对象内，不能称为“栈上定长 vector” |

这里按 C++26 提案与工作草案讨论，不承诺本机 GCC 15.1 完整实现这些设施。
新版本可能已有部分或完整支持，迁移时应查对应编译器和标准库版本。

### 3.3 标准证据与实现证据

规则由对应版本标准及适用修正确认；本机编译运行只验证该工具链和路径。
编译器可能有扩展、缺陷或未实现部分，不能用“编译成功”推翻标准约束。
本轮例子中 GCC 的旧逗号下标兼容行为就是扩展边界；
`mdspan` 在 GCC 15.1 缺失是实现进度，范围格式化缺少额外冒号则是源代码错误。

迁移流程是：确认标准归属 → 检查特性宏及版本 → 编译正反例 → 验证边界与运行输出。
不同 C++ 模式的翻译单元要一起链接，还要核对 ABI、ODR、头文件条件定义及库的兼容保证，
不能由“C++14/17/20/23 可以分别编译”直接推导任意混编安全。

## 常见陷阱

1. “标准已采纳”不等于“本机工具链已完整实现”，`-std=c++26` 也不是完整实现承诺。
2. 无界的数学序列不能照搬为无界 int 递推；检查生成器的加法、乘法与循环增量。
3. ranges::take 限制消费数量，不替源算法修复溢出，也不保证绝不恢复到下一个元素。
4. expected 不强制处理错误，不自动捕获分配失败，也不让 `.error()` 在成功态合法。
5. 学习笔记应区分标准保证、本机观察和性能假设，不把偶然输出推广为通用结论。

## 练习（毕业设计）

1. 实现有明确整数上界的素数生成器，检查 N 后求前 N 项的平方根并格式化输出。
2. 为偶数平方函数测试 0、1、最大可接受数量及超上界，验证返回数量与错误。
3. 测试空参数包、包索引越界及删除的 double 重载，作为预期编译失败案例。
4. 从 README 选一个知识点，对照标准条款、本机输出和错误场景各写一条结论。
