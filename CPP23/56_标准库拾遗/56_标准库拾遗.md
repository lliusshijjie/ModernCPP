## 一、底层原理

### 1.1 contains / starts_with / ends_with：把"意图"写回代码

`url.find("x") != std::string::npos` 流毒三十年——读者要倒推
"这是在判断包含？"；`npos` 比较是实现的细节不是业务的意图。
C++23（P1679）给 string / string_view 补上三个语义化查询
（C++20 就有 starts_with/ends_with，contains 是 23 的新增），
一行代码终于说人话。

### 1.2 move_only_function：拆掉 function 的可拷贝枷锁

std::function 的设计约束是**可拷贝**——于是捕获了 unique_ptr、
线程、文件句柄的 lambda 一律进不去（拷贝构造硬性要求）。
C++23（P0288）的 `std::move_only_function` 砍掉拷贝、
换来**任意可调用**（含 move-only）的存储；调用约定、
const 性、noexcept 都进了模板签名——比 function 更精确的类型刻画。

| | std::function | move_only_function |
|---|---|---|
| 可调用物 | 必须可拷贝 | 只要可调用 |
| 捕获 unique_ptr | ✗ 编译错 | ✓ |
| const 调用约定 | 单一版本 | `const`/非 const/`noexcept` 分开 |
| 存储开销 | 可能堆分配（同） | 同 |
| 置空/判空 | = nullptr / bool | 同 |

### 1.3 std::stacktrace：把 __FUNCTION__ 宏考古现场收编

C++ 从此有标准的**运行时栈回溯**（P0881）：`stacktrace::current()`
抓帧集合，`to_string(st)` 全量文本，单帧 `stacktrace_entry` 有
`description()`（符号名）与 `source_file()/source_line()`
（若符号信息可用）。诊断、异常上下文（`std::basic_stacktrace`
可塞进异常对象，第 51 课错误处理的增强件）有了标准件。

**本机如实标注**：MinGW 原生工具链的符号信息有限——
实测 description() 可能只给内部符号名甚至空串；
Linux（libbacktrace）/MSVC 下函数名、文件行号更完整。

## 二、具体语法

```cpp
#include <stacktrace>
#include <functional>

std::string url = "https://cpp.dev";
url.contains("cpp");  url.starts_with("https");  url.ends_with("dev");
std::string_view(url).contains(".");

std::move_only_function<int()> f =
    [blob = std::make_unique<std::string>("hi")] {
        return (int)blob->size();
    };
f();                                    // 2
f = nullptr;                            // 置空
if (f) {...}                            // 判空

const std::move_only_function<int() const> cf{...};  // const 调用约定版

auto st = std::stacktrace::current();   // 此刻调用栈
st.size();                              // 帧数
std::to_string(st);                     // 全量文本
for (const auto& e : st) e.description();
auto st2 = std::stacktrace::current(1); // 跳过 1 帧（从调用者算起）
```

规则细则：

- contains 参数是 string_view——string/string_view/字面量通吃，
  **不含**"是否为子串序列"之外的语义（正则请用 regex）
- `starts_with/ends_with` 是 C++20 就有的（string 侧），
  contains 是 C++23 新增——三件套终于凑齐
- move_only_function 的**调用后置空**不等同 operator() 后失效——
  它无" Engaged"检查，空调用是 UB（先判 `if (f)`）
- move_only_function 不可拷贝：容器存它后容器也只能移动
  （vector<move_only_function> 本身仍可用，元素不能拷出去）
- stacktrace 抓帧有运行时成本：别在热循环里调用；
  current(skip) 从第 skip+1 层开始抓
- `basic_stacktrace` 可作为异常成员：`throw Err{..., stacktrace::current()}`

## 三、实际应用与最佳实践

### 3.1 场景：可移动任务队列（示例 ③）

线程池/异步队列的任务要捕获独占资源（缓冲、连接、promise）——
`vector<move_only_function<int()>>` 一行到位；旧世界只能
shared_ptr 包装或裸 new 手管。

### 3.2 场景：错误上报带现场（示例 ③）

捕获点顺手 `stacktrace::current()` 存进错误对象——
第 51 课的三种错误通道（异常/错误码/expected）都能携带
"出错时的调用路径"，日志不再靠人肉猜层级。

### 3.3 最佳实践清单

1. 子串判断三连一律语义化接口；`find(...) != npos` 冻结退役
2. 回调存储默认 std::function；**捕获独占资源/对调用约定有要求**
   时换 move_only_function
3. 空可调用检查是调用方责任：`if (f) f();`
4. 栈回溯限诊断路径（错误、崩溃、慢路径）；热循环禁用
5. 符号质量按平台分级设计：核心信息别只依赖 source_line()

## 常见陷阱

1. **move_only_function 空调用是 UB**：不像某些实现给异常——
   `f = nullptr; f();` 没有守卫；先判空
2. 捕获独占资源后还想**拷贝队列**：vector 里的 move_only_function
   拷不动——整体 move（或重新设计共享语义）
3. 本机（MinGW）以为 to_string 会给出漂亮函数名+行号：
   符号信息可能缺失（如实标注），Linux/MSVC 才完整——
   程序逻辑别依赖栈内容
4. contains 大小写敏感：`"Abc".contains("abc")` 为 false——
   忽略大小写的需求自己 lower 后再查
5. stacktrace 抓的是**当前线程**：异步任务的现场要当场抓
   （存进任务对象），事后在别的线程抓不到
6. starts_with(P) 的 P 是 string_view：传 `{'h','i'}` 之类的
   initializer_list 有专门重载，别混（string 版三家族：串/字符/列表）

## 练习

1. 把手头代码里的 `find(...) != npos` 全局替换为 contains，
   统计替换行数与可读性变化。
2. 写 `CallbackRegistry`：存 `move_only_function<void(int)>`，
   支持注册/触发/清空；故意触发已置空项验证陷阱 1（加 if 防御）。
3. 自定义异常携带 `std::basic_stacktrace`，在三层深的调用里抛出，
   最外层 catch 打印 `to_string(st)`（本机符号贫乏也照实打印）。
4. 性能实验：`stacktrace::current()` 在循环里抓一万次，
   对比注释掉后的总耗时，量化"诊断不进热循环"的理由。
