## 一、底层原理

### 1.1 字符串查询直接表达意图

`string` 和 `string_view` 的 `starts_with/ends_with` 从 C++20 起可用，
`contains` 是 C++23 新增。只需要布尔子串查询时，可以把完整的
`find(x) != npos` 改成 `contains(x)`；需要位置、起始搜索位置或后续切片时仍用 `find`。
它们按字符特征 traits 比较，不是正则、Unicode 归一化或自动忽略大小写的搜索。

### 1.2 move_only_function 保存无需复制的调用对象

`std::function` 通过复制目标实现可复制包装，不能直接保存捕获 `unique_ptr` 的不可复制闭包。
`std::move_only_function` 删除包装器的复制操作，可保存这类闭包，
并支持签名中的 const、引用限定符和 noexcept。

| 方面 | `std::function<R(Args...)>` | `std::move_only_function<R(Args...)>` |
|---|---|---|
| 包装器复制 | 可复制 | 不可复制，可移动 |
| 目标要求 | 可复制且符合调用要求 | 可由传入参数构造且符合签名的调用要求 |
| const 调用 | const 包装器仍可调用可变目标 | 由签名是否含 const 明确约束 |
| 空调用 | 抛 `bad_function_call` | 违反前置条件，行为未定义 |
| 分配 | 可能分配 | 可能分配，不保证更省或更快 |

不是任意可调用物都能放进去：构造、返回值、参数、cv/ref 与 noexcept 必须匹配。
普通转发构造需要能构造目标；`in_place_type` 还可直接构造不可移动目标，
移动包装器不等于每次都必须移动目标对象本身。

### 1.3 stacktrace 记录当前线程的捕获现场

`std::stacktrace` 是 `basic_stacktrace` 的常用别名。
`current()` 返回当前线程此刻的调用路径，可能为空；它不会自动记录异常最初抛出的位置，
也不会跨线程补全异步任务的逻辑调用链。要保留错误发生点，应在那里捕获并随错误传递。

帧数和符号信息依赖实现、优化、内联、调试符号与部署配置，任何平台都不保证函数名和行号齐全。
`description()`、`source_file()` 可为空，`source_line()` 可为 0。

## 二、具体语法

```cpp
std::string url = "https://cpp.dev";
url.contains("cpp");                          // string_view / 单字符 / C 字符串重载
url.starts_with('h');
url.ends_with(std::string_view{"dev"});
std::string_view tail = std::string_view{url}.substr(8); // 借用 url

std::move_only_function<int()> f =
    [p = std::make_unique<int>(7)] { return *p; };
if (f) { int result = f(); (void)result; }
f = nullptr;

const std::move_only_function<int() const> cf = [] { return 3; };
cf();
std::move_only_function<void() &&> rvalue_only = [] {};
std::move(rvalue_only)();                      // 仅约束调用对象的类别，不自动置空

auto st = std::stacktrace::current();
auto limited = std::stacktrace::current(1, 8); // 跳过捕获结果中的第一帧，最多取 8 帧
std::string text = std::to_string(st);
```

这些片段需相应包含 `<string>`、`<string_view>`、`<functional>`、`<memory>`、
`<utility>` 与 `<stacktrace>`。

三个字符串查询各有 `string_view`、字符和字符指针重载，没有专门的 `initializer_list` 重载。
`contains("")` 为 true；单字符重载可以搜索嵌入的 NUL，C 字符串重载在 NUL 处终止。

调用包装器不自动消费或清空它，`&&` 限定也不保证只调用一次。
移动后的源包装器处于有效但值未指定的状态，不能依赖它必为空。
目标也可以是非拥有的 `reference_wrapper`，此时仍需管理被引用对象的生命期。

`stacktrace::current()` 自身 noexcept；初始化失败可返回空结果。
符号查询和文本转换仍可能因分配失败抛异常；不能由此推导整个错误上报路径不会抛异常，
也没有标准的异步信号安全保证。

## 三、实际应用与最佳实践

示例中的 `TaskQueue` 保存独占资源回调；`run_all()` 每次调用会重新执行非空任务，
没有自动出队或一次性消费语义。任务是否可重复执行取决于业务与闭包本身。
包含 `move_only_function` 的 vector 可以移动，正常的元素复制与容器复制则无法完成；
不能仅凭某些类型 traits 的结果认定容器复制表达式可用。

`string_view` 必须借用仍然存在的字符串。`std::string_view tail = url.substr(8)`
引用的是临时 `string` 的数据，分号后悬垂；应先转成视图再对视图 `substr`。
底层 url 被销毁或发生使字符存储失效的修改时，tail 也会失效。

栈回溯适合诊断路径，捕获与符号化都有成本；先测量再决定采样频率。
崩溃处理器另有平台限制，不能把普通错误路径里的 stacktrace 直接视为通用崩溃处理方案。

## 常见陷阱

1. 空 `move_only_function` 与空 `function` 的调用规则不同，调用前须保证有目标。
2. 不可复制闭包并不要求用 shared_ptr 改成共享所有权；可使用 move_only_function 或直接保存具体闭包类型。
3. `std::move(f)` 本身只是类别转换，既不执行回调也不清空它。
4. 字符串字面量数组本身没有 `.contains()` 成员，使用 `string_view{"Abc"}.contains("abc")`。
5. `find != npos` 只有语义完全相同的布尔查询才能替换；不要全局机械替换。
6. 栈为空、符号缺失或帧数变化都不能用来判定业务调用是否执行。
