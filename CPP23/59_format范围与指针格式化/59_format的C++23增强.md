# 第 59 课 · C++23 范围格式化与指针格式化辨析

> 标准：C++23；代码：`59_format_ranges.cpp`。
> 本机 GCC 15.1.0 已支持本课的范围嵌套说明符与 `void*`/`nullptr` 格式化，示例链接 `-lstdc++exp`。
> 前置：第 36 课 format、第 49 课 print。

## 一、底层原理

### 1.1 范围格式化复用元素 formatter

C++23 的范围格式化将输入范围逐元素格式化，并添加分隔符和括号。
元素必须可格式化，范围本身也必须满足对应 formatter 的约束。
大多数普通容器可直接输出，但不是只要有 begin/end 就一律可用：
例如引用类型递归等于自身的范围会被默认禁用，字符串另有专用 formatter。

| 形式 | 默认输出示例 |
|---|---|
| `vector<int>{1,2}` | `[1, 2]` |
| `set<int>{1,2}` | `{1, 2}` |
| `map<string,int>{{"a",1}}` | `{"a": 1}` |
| `vector<string>{"x","y"}` | `["x", "y"]` |
| `vector<char>{'a','b'}` | `['a', 'b']` |
| 嵌套 vector | `[[1, 2], [3, 4]]` |

字符串/字符元素在没有显式元素说明符时，默认使用调试格式，添加引号并转义。
它不是任意数据结构的 JSON 或 CSV 序列化协议。

### 1.2 说明符有两层，额外冒号不能少

```text
{:[填充与对齐][宽度][n][范围类型][:元素说明符]}
```

| 格式串 | 含义 |
|---|---|
| `{}` | 默认范围输出 |
| `{:n}` | 仅去掉当前层外括号，仍使用默认分隔符 |
| `{:>15}` | 整体宽度至少 15，靠右 |
| `{::>4}` | 每个元素宽度至少 4，靠右 |
| `{::.2f}` | 浮点元素保留两位小数 |
| `{::?}` | 每个字符串/字符元素使用调试格式 |
| `{::}` | 显式空元素说明符，取消默认元素调试模式 |
| `{:s}` | 字符范围作为一个字符串 |
| `{:?s}` | 字符范围作为一个带引号、转义的字符串 |

`m` 可以把 pair/二元 tuple 的范围按映射形态输出；`s`、`?s` 要求元素类型与输出字符类型相同，
且不能再搭配 n 或元素说明符。嵌套范围的每一层都按自己的规则解析。
`{:.2f}` 没有额外冒号，不能用于浮点 vector；`{:?}` 也不是通用范围语法。
因此相关编译错误不是“标准库未实现”。

### 1.3 指针格式化从 C++20 就存在

C++20 已有 `void*`、`const void*`、`nullptr_t` 的 formatter；
普通对象指针 `int*` 等不能直接使用它们的格式化接口，需要显式转为 `const void*`。
字符指针另有字符串含义：`{}` 输出 C 字符串内容，不是地址。

```cpp
int x = 5;
int* p = &x;
std::format("{}", static_cast<const void*>(p));
std::format("{:p}", static_cast<const void*>(p));
std::format("{}", nullptr);
```

C++23 基础指针表示类型为默认或 p，在提供 uintptr_t 的实现上是相应整数的十六进制表示加 `0x`。
指针到整数的映射依实现，不能从语言规则推导“空指针转整数必为 0”；本机通常打印 `0x0`。
不需要为了打印地址手工转 uintptr_t，也不能用这种转换承诺跨平台固定输出。

P2510R3 是 C++26 的指针格式增强（补零与大写 P），实现可能作为修正回移到旧模式；
它并没有允许任意 `T*` 直接格式化。不同标准模式与库版本的扩展支持需要分别验证。

## 二、具体语法

```cpp
std::vector<double> v{1.5, 2.0};
std::println("{::.2f}", v);                 // [1.50, 2.00]
std::println("{:n:.2f}", v);                // 1.50, 2.00
std::vector<std::string> words{"a b", "c\"d"};
std::println("{}", words);                  // ["a b", "c\"d"]
std::println("{::}", words);                // [a b, c"d]
std::vector<char> text{'a', '\n'};
std::println("{:?s}", text);                // "a\n"
```

需要包含 `<format>`、`<print>` 与对应容器头文件。
宽度是最小宽度，不会截断容器；例如 `[1, 2, 3]` 有 9 个显示列，
`{:>15}` 会在前面填 6 个空格。`{:n}` 不删除嵌套容器内部的括号，也不改变元素本身的格式。

## 三、实际应用与最佳实践

日志快照可直接格式化小容器，大容器先截断或采样。
对单趟范围做格式化也会消费它，可能产生遍历副作用或抛异常；不要默认日志与程序状态完全无关。
无序容器的输出顺序也不保证稳定。

自定义元素类型可以提供 formatter；自定义范围类型可按标准要求特化 `format_kind`，
也可以提供自己的 formatter 并用 `range_formatter` 配置分隔符和括号。
不能把默认范围种类简单等同于具体容器名称，它还依据 key_type、mapped_type 与元素结构等规则确定。

正式 CSV 需要处理逗号、引号和换行，正式 JSON 需要遵循协议中的类型和转义规则，
不能只凭输出形似就把调试格式当序列化结果。

## 常见陷阱

1. 范围元素精度用 `{::.2f}`；整体对齐用 `{:>15}`，元素对齐用 `{::>4}`。
2. 字符/字符串元素默认已转义，给范围加 `{:?}` 是错误语法。
3. `int*` 不可格式化不是 GCC 缺陷；地址用 `static_cast<const void*>(p)`。
4. 不依赖空指针的整数值或运行时地址固定，地址测试应避免硬编码随机值。
5. 自定义元素没有 formatter 时，容器也不会自动知道如何输出它。
6. `views::take` 一类截取视图可能改变默认范围种类，输出括号形态应按最终类型判断。

## 练习

1. 对比 map 与 vector<pair<string,int>> 默认输出，并尝试 `{:m}`。
2. 对比 `{}`、`{::}` 与 `{::?}` 对引号、换行和反斜杠的处理。
3. 分别测试整体宽度和元素宽度，计算实际填充数量。
4. 输出字符指针的内容与地址，保留 `int*` 直出为预期编译失败测试。
