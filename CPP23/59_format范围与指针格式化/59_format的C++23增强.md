# 第 59 课 · std::format 的 C++23 增强：范围与指针格式化（C++23）

> 所需标准：**C++23**（`-std=c++23`；本机 g++ 15.1.0 需链接
> `-lstdc++exp`）｜ 讲解：本文件 ｜ 独立代码：`59_format_ranges.cpp`
> ⚠ 本机如实标注（g++ 15.1.0 实测）：**范围格式化可用**；
> **元素级说明符嵌套、`{:?}` 转义形态、指针 `{}`（P2510）尚未实现**
> ——示例均给替代写法，见"常见陷阱"与示例注释
> 前置：第 36 课（format 基础）；第 49 课（print——本课的输出端）

## 一、底层原理

### 1.1 容器直出：格式化的"最后一堵墙"倒了

C++20 的 format 一切好用，唯独容器要自己循环拼——
调试打印向来是"手写 for + 逗号分隔"的天下。
C++23（P2286）把**整个 range 家族纳入格式化**：

| 元素 | 形态 | 例子 |
|---|---|---|
| 序列（vector/deque/list） | `[a, b, c]` | `[1, 2, 3]` |
| 集合（set） | `{a, b}` | `{7, 8}` |
| 映射（map） | `{"k": v}` | `{"a": 1, "b": 2}` |
| string 元素 | 双引号 | `["x", "y"]` |
| char 元素 | 单引号 | `['a', 'b']` |

引号规则与 Python 的 repr 一脉相承——**调试输出天然可辨类型**。

### 1.2 范围格式说明符：作用域分层

```
{:[range-fill-and-align][width][n][嵌套元素说明符]}
```

- `n`：去掉外层括号（csv 直出）
- 宽度/对齐作用于**整个范围**（先括号再对齐）
- 嵌套部分下传给**元素格式化器**——标准设计如此，
  本机实现暂缺（如实标注）

### 1.3 指针格式化（P2510）：标准有、本机无

标准语义：`format("{}", ptr)` 输出 `0x` 开头的地址
（等价 `{:p}`；空指针输出 `0x0`）。本机 g++ 15 未实现——
**替代写法**：`format("{:#x}", reinterpret_cast<uintptr_t>(p))`
（示例 ③；空指针恒 `0x0`，可做确定性断言）。

## 二、具体语法

```cpp
std::vector<int> v{1, 2, 3};
std::map<std::string, int> m{{"a", 1}};
std::print("{}", v);         // [1, 2, 3]
std::print("{:n}", v);       // 1, 2, 3（无括号）
std::print("{:>12}", v);     // 宽度/对齐作用整体
std::print("{}", m);         // {"a": 1}
std::vector<std::vector<int>> g{{1, 2}, {3, 4}};
std::print("{}", g);         // [[1, 2], [3, 4]]（递归）

// 标准语义（本机暂缺，注释保存）：
// std::print("{:.2f}", std::vector<double>{1.5});  // 元素级说明符
// std::print("{:?}", vec_of_strings);              // 转义形态
// std::print("{}", ptr);                           // 指针（P2510）

// 本机指针替代：
std::print("{:#x}", reinterpret_cast<std::uintptr_t>(p));
```

规则细则：

- 可格式化的范围：**元素可格式化**即可（自定义类型给自己的
  元素写 formatter，容器跟着就能打）
- 自定义容器实现 `begin/end` 且满足 range 概念即自动获益
- 序列/集合/映射三形态由**种类**决定（map 出 `"k": v`）；
  自定义关联类型可特化 `formatter` 的 `debug`/种类行为
- `std::print` 家族同享（第 49 课）——println 容器一行
- 嵌套深度无特殊限制（递归格式化）

## 三、实际应用与最佳实践

### 3.1 场景：调试/日志的状态快照（示例 ③）

一行 `print("state {} samples={}", name, samples)` 顶过去
六行循环——日志从此"看见数据结构"。

### 3.2 场景：csv/报告直出（示例 ②）

`{:n}` 去括号、逗号分隔——配合 join 语义的场景（第 34 课 split
的逆操作）零样版。

### 3.3 最佳实践清单

1. 调试打印一律容器直出——手写循环拼接冻结退役
2. 大容器先截断再打印：`v | views::take(20)`（第 33 课）
   再格式化——日志爆炸多半来自无意识的全量打印
3. 类型可辨性靠默认引号规则；自定义类型写 formatter 时
   保留这个习惯（字符串元素加引号）
4. 本机元素级精度/指针格式化用替代写法并注释标准语义——
   编译器升级后切回
5. 自定义类型从"元素 formatter"做起，容器格式化免费获得

## 常见陷阱

1. **以为格式说明符作用于每个元素**（如 `{:>4}` 想右对齐
   每个数字）：宽度/对齐作用于**整个范围字符串**——
   元素级控制本机未实现
2. 指针直接 `{}`（本机）编译错——P2510 未落地；
   `uintptr_t` 转换是当前正道
3. `{:n}` 只去**外层**括号：嵌套容器的内层括号保留
  （`[[1, 2], [3, 4]]` 的内层不动）
4. 循环里对同一大容器反复 `{}`：每次全量序列化——
   性能敏感日志先采样
5. 自定义类型没写 formatter 却直接 `{}` 容器：
   编译错发生在元素层——报错信息会指向元素类型，
   别误以为是容器不支持
6. 期待输出固定宽度的地址对齐表：`{:#x}` 的位数随地址值变——
   对齐要配宽度 `{:>18}` 之类在整体上做
